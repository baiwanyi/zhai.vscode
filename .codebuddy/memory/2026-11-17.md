## 作品面板闪退修复（两层 Popover 改回单容器）

**现象**：选中作品行后作品面板弹出即消失（用户实测）。

**原因**：当时用两个独立 `Popover`（选择器 + 作品面板）共用按钮锚点，点击作品行时一层关闭、另一层打开，两层在同一帧一关一开，新面板仍被判为外部交互而立即收起——与项目早前「下拉菜单打开面板」的闪退同源，属于 Radix 层栈的固有问题，不是锚点没对上。

**修复**：退回单个 `Popover`，`layer` 状态只决定内容与宽度（picker 层 w-56 / project 层 w-72），浮层全程不重新打开；删除 `PopoverAnchor` 替身锚点、`handleProjectOpenChange` 与两个开合回调（合并为 `handleOpenChange` + `closeLayer`）。作品面板仍是独立组件、独立宽度，只是不再独立成层。

**结论（供后续复用）**：本项目的浮层切换一律用「同一 Popover 内换内容」，不要用「一个浮层开另一个浮层」；`AiChatContextMenu`、`AiChatContextProjectPicker`、`AiChatContextSourcePicker` 的头部注释里已写明该约束。

**验证**：eslint 0 problems、prettier 通过、`tsc --noEmit` 退出码 0；交互仍需在扩展宿主内手工复验。

## 「添加上下文」改用 DropdownMenu + HoverCard 双层结构

按用户要求把入口从「单 Popover 内换内容」改为：一级菜单用 `@components/ui/dropdown-menu`（选择笔记本 / 笔记 / 文章 / 作品 + 分隔线后的规则），任一项悬停即在其右侧用 `hover-card` 展开对应面板。根列表不再是面板内的一层视图，`AiChatContextRootList` 随之删除。

**关键取舍**：
- 菜单必须 `modal={false}`——模态菜单会给页面挂 `pointer-events:none` 并开启 FocusScope 锁焦，二级面板里的点击与输入会直接失效。
- 菜单需豁免面板内部的指针与焦点事件：`DropdownMenuContent` 的 `onPointerDownOutside` / `onFocusOutside` 里按 `closest('[data-slot="hover-card-content"]')` 判断，命中则 `preventDefault()`，否则点面板条目会先收起菜单、连带卸载面板（与历史上「两层浮层同帧一关一开」同源）。
- 面板开合受控：`activeKey` 单一状态决定展开项；关闭回调只认领自己那一项（上一项的 closeDelay 定时器会晚于下一项的 openDelay 触发，误清会闪掉刚打开的面板）。
- 角色拆分：`PickerEntry` 组件承载「DropdownMenuItem + ChevronRight + 右侧 HoverCard」，`onSelect` 里 `preventDefault()` 保住菜单，供触摸 / 键盘展开面板。
- 作品面板仍是同一 hover-card 内换内容（作品列表 → 分类面板，宽度 w-64 → w-72），返回只换回列表。
- 检索框新增 `autoFocus` 开关并默认 `false`：悬停面板靠触发项指针停留维持，挂载即抢焦点会让触发项失焦、面板 300ms 后自动收起。

**返工（用户反馈「等不到鼠标移到就消失」）**：根因是 hover 的开合交给了 Radix——`HoverCardTrigger` 的 pointerleave 会按 closeDelay 直接收起，而菜单项与面板之间有 4px 空隙，指针横跨时那一刻既不在菜单上也不在面板上，缩放窗口或稍慢移动就会在到达前关掉。

### 修复列表标题不截断

**现象**：长标题把行撑开、`truncate` 不生效。

**原因**：Radix `ScrollArea` 在 Viewport 里套了一层测量层 `<div style="min-width:100%; display:table">`（已核对 `@radix-ui/react-scroll-area` 的 dist 源码）。`table` 布局按内容宽度伸展，行内 `flex-1 min-w-0 truncate` 拿不到可收窄的宽度，整层被撑成横向溢出。

### 修切到「设定」时 kind 非法：设定分类不发候选查询

**现象**：作品面板切到「设定」报 `ai/context/query 参数非法：kind 须为 note / article / chapter / character / outline`。

**根因**：`useContextQueryTarget(query, target)` 里的 `target` 直接由 `tab` 生成，而 `AiContextProjectTab` 含 `'setting'`；宿主 `CONTEXT_ITEM_KINDS` 白名单只有 5 类（设定走 `ai/context/sections`），于是切到设定就发了一个宿主不认的 kind。类型层不会报——`AiContextItemKind` 恰好也含 `setting`。

**修复**：设定分类传 `null` 给 `useContextQueryTarget`，让 hook 走 reset 分支（清空候选、不发请求）；切回章节 / 人物 / 大纲时 target 从 null 变对象，自动重新 select。
