## sonner 提示集中到 Workflow 面板 & CodeBuddy 登录态记忆

- 现象一：同一条宿主反馈在两个面板各弹一次 sonner。原因：两个 Webview 都挂了 Toaster 且都订阅 `toast` 通道。改为：`ToastService` 的视图计数与广播只由 `AiChatViewProvider`（Workflow 面板）参与，`dashboardProvider` 与 `dashboardScreen` 不再订阅该通道，仪表盘 sonner 只承载本面板页面内的操作结果；Workflow 未打开时仍回退原生通知。
- 现象二：已登录 CodeBuddy 仍显示登录引导。原因：`AiChatEmptyState` 无条件渲染 `AiChatCodebuddyState`，且 `checkReady()` 恒为 ready，UI 无从判断登录态。改为：
  - 新增 `modules/ai/providers/codebuddyLogin.ts`，用 globalState 的站点级键（`ai.codebuddyAuthed.{站点}` / `ai.codebuddyUser.{站点}`）记录登录态，激活时 `initCodebuddyLogin(context.globalState)`。
  - `zhai.ai.loginCodebuddy` 登录成功后 `rememberCodebuddyLogin(site, userName)`；`generate` 成功完成时补记一次（覆盖只在 CLI 侧登录的用户）。
  - `AiRuntimeInfo` 增加 `loggedIn` / `loggedInUser`，`chatService.getRuntimeInfo` 按当前站点读取。
  - `AiChatCodebuddyState` 按登录态分两态：未登录给引导与登录按钮，已登录给「已登录 CodeBuddy（站点 / 账号）+ 可直接开始」说明。
- SDK 只暴露 `authenticate` / `logout`，没有登录态查询接口，故采用「登录成功 / 生成走通」作为确认依据；升级前已登录的用户首次仍需点一次登录或成功发一条消息。

- 现象：章节标题过长时折成多行，`truncate` 不生效。根因是 `ItemContent`（`flex flex-1 flex-col`）缺 `min-w-0`，flex 子项默认 `min-width: auto` 无法收缩，内容宽度把整行撑开。
- 只补 `min-w-0` 后变成硬切、没有省略号：`ItemTitle` 基础类含 `flex`，`text-overflow: ellipsis` 在 flex 容器上对匿名文本项不生效。
- 最终写法（`PressVolumeSection.tsx` 章节行）：`ItemContent className="min-w-0"`、`ItemTitle className="line-clamp-none block w-full truncate text-xs"`、`ItemActions className="shrink-0"`。`line-clamp-none` 用于在 twMerge 中顶掉基础类的 `line-clamp-1`，同时 `block` 顶掉 `flex`；产物 CSS 中 `.truncate`（overflow/text-overflow/nowrap）排在 `.line-clamp-none` 之后，故块级 + 省略号成立。
