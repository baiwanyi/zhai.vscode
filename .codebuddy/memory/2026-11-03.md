## 功能：批次封面点击选图与裁剪、导入时正文图片随文复制

- 协议层新增两个方法：`wechat/cover/source` 把存储根内的封面原图读成 data URI（Webview 里 asWebviewUri 与页面不同源，直接 drawImage 会污染画布），`wechat/article/cover` 接收裁剪后的 jpeg/png data URI；两者都在 `shared/types/wechat` 收窄，`HostMethodName` 与 `wechatRoutes` 同步登记。
- 宿主：`WechatIssueService.readCoverSource` 校验扩展名、存储根归属与 12MB 体积上限后内联；`saveArticleCover` 解码 data URI、写入批次目录 `images/cover-{文章 id}.jpg`，随后只回写 `cover_path`（新增 `updateWechatArticleCover`）并刷新批次更新时间。
- 前端：新增 `WechatCoverDialog`，在 FormDialog 内完成「选图 → 2.35:1 取景框拖动/缩放 → canvas 导出 1175×500 jpeg」；`useWechatIssues` 增加 `pickCover` / `readCoverSource` / `saveArticleCover` 三个动作，`DashboardWechatPost` 组合成一次交互并把结果交给弹窗。
- 封面入口：`WechatIssueCard` 的首篇主图与子列表缩略图都可点击（原生 button 包裹，isBusy 时禁用），`WechatIssueList` 透传 `onPickCover`。
- 导入：`importArticle` 逐条解析正文图片引用（`@zhai/`、`/` 开头、相对路径与绝对路径），复用 `locateWechatImage` 定位源文件，复制到批次 `images/`（重名按「主干 2.扩展名」顺延），引用改写为相对批次文件的 `images/{文件名}`；外链、data URI 与越界路径保留原样，单张失败只记日志。
- 合并：批次合并改为解析源文件后重建，正文图片一并迁到目标批次 `images/` 并改写引用（源批次目录随后删除）；`issueDocument.copyWechatArticleDoc` 因此无人使用而删除。
