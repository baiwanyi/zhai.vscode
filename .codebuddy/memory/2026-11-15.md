## 查找条审查修复（SearchPanel + useDocumentSearch）

2 项 minor（空查询文案、输入防抖），实施中另修正一处受控输入的隐患。

**empty 查询显示「无结果」（minor）**：初始 state 与 `close()` 都把 `matchCount` 置 0，`open()` 无选中文本时不 `run`，于是刚打开（或手动清空关键词）就显示「无结果」。`readCounterLabel` 增加 `query` 参数：空查询返回空串（`InputGroupText` 的 `min-w-14` 保留占位，宽度不跳动）。

**每键全量遍历 + 重建装饰 + 滚动（minor）**：`setQuery` 原来直接 `run`（遍历全文、重建最多 500 个装饰、`scrollIntoView`）。改为 `SEARCH_DEBOUNCE_MS = 150` 防抖，新增 `pendingQueryRef`；`goNext` / `goPrev` 先 `runPendingQuery()` 结算窗口里的输入（否则跳的是上一个关键词的命中）；`close` / `open` / 卸载都清理定时器——`close` 不清会让 150ms 后 `run` 把 `isOpen` 顶回 true，等于关不掉。

**实施中修正的隐患（受控输入）**：最初只把待查关键词存 ref、不改 state，而输入框是受控的（`value={state.query}`）——防抖期间父层任何重渲染都会把刚敲的字符吞回去。改为 `setQuery` 立即 `setState({ ...prev, query: nextQuery })` 同步回显，只把命中重计算放进防抖窗口。

**suggestion 未采纳**：`IGNORE_OPEN_CHANGE` 加 `_isOpen` 参数会被 `@typescript-eslint/no-unused-vars` 拒绝（项目未配 `argsIgnorePattern`），保持无参写法；`role="search"`、计数 `aria-live`、打开时全选查询文本、`run` 未查 `isDestroyed`、超长 query 上限仍只标注。

**验证**：`eslint` 0 problems（中途 1 条 `_isOpen` 未使用，已回退）、`prettier` 通过、`tsc --noEmit` 通过；该模块无既有单测。

## CopyButton 审查修复

2 项 minor 落地：

**无可访问名称（minor）**：`tooltip` 只是 Radix 浮层，不会给按钮加 `aria-label`，图标按钮在读屏里只有一个「按钮」；从 `ToolbarBody` 抽出来时把旧代码这处缺陷一起搬了过来（同工具条其它图标按钮都有 aria-label）。补 `aria-label={isCopied ? '已复制' : '复制'}`，与 tooltip 同源。

**异步后卸载（minor）**：`handleCopy` 在 `await copyToClipboard` 之后无条件 `setIsCopied(true)` 并新建 `window.setTimeout`；工具条按选区 key 重挂载，复制途中换选区就会卸载本组件，cleanup 已跑过 → 新定时器无人清理、1.2s 后回调已卸载组件。加 `isMountedRef`（effect 里 mount 置 true、cleanup 置 false，显式复位以避免 StrictMode 双执行把标记永久置 false），await 后先判挂载再动状态。

**suggestion 未改**：失败时不清除上一次成功提示（清掉会让图标在失败瞬间闪回，更吵）；空文本仍可点击（当前唯一调用方 `MIN_SELECTION_CHARS = 2` 使其不可达；将来复用到别处再加 `disabled`，注意 Button 禁用后 tooltip 不再弹出）。
