# 2026-11-21

## 微博卡片默认显示全文（不再手动点「展开全文」）

- 长文卡片改为自动展开：正文节点首次进入视口（提前 240px）即请求 `weibo/longtext`，拿到全文后整段替换摘要；分页新增的卡片各自按视口触发，避免一次性把整页长文全部请求出去。
- 请求加 ref 占位，同一卡片同一时刻只允许一条在飞，规避严格模式下的双次 effect 与连点。
- 失败策略：自动展开属后台补全，失败不弹 toast，只保留「重新加载全文」按钮；仅用户主动点击时才 `toastError`。
- 加载中给「正在加载全文…」文案；未进视口或失败时保留可点按钮作兜底。
- `useHasEnteredViewport` 泛型化（默认仍是 `HTMLSpanElement`），以便把 ref 挂到正文 `<p>` 上，其它调用点无需改动。
- 校验：`tsc --noEmit`、ESLint、Prettier 均通过。

## 微博「添加到 AI 对话」补齐长文全文

- `weibo/addToChat` 改为与保存笔记同口径：载荷收窄后先走 `expandLongText`（主贴用 mblogid、转发体用数字 id），取全文失败只记日志并保留摘要，不阻断添加。
- 引用对象的 `isTruncated` 语义收紧为「补全也失败」；补全成功即复位，芯片上的截断角标只在真正失败时出现。
- 前端 `CHAT_TIMEOUT_MS` 由 20s 放宽到 60s：该动作现在可能先取主贴 + 转发两篇全文，受 1.2s 节流与退避约束。
- 新增 3 条单测（主贴长文取全文、非长文不请求、取全文失败保留摘要）。
- 校验：`tsc --noEmit`、ESLint、Prettier 通过；`weiboSaveNote` / `weiboPostNote` / `weiboFeed` / `weiboTimeline` 共 115 项测试通过。

## 输入卡片生成态光晕压回卡片背面

- 现象：光晕糊在卡片正面。根因是负 z-index 子层按层叠规则只画在父级背景之上、内容之下——父元素自己的 `bg-composer` 遮不住它，卡内区域整片透出 conic 背光。
- 修法：`AppComposer` 在光晕之后再垫一层同色底衬（`bg-composer` + `rounded-2xl`，`pointer-events-none`），层级改为光晕 `-z-20` < 底衬 `-z-10` < 内容；光晕只剩卡片边缘的溢出可见。
- `AiTextareaField` 原有底衬不受影响（`InputGroup` 自带 `relative`，绘制在底衬之上）。
- 校验：`tsc --noEmit`、ESLint、Prettier 通过；`vite build` 成功，产物 CSS 含 `.-z-20` / `.-z-10` 两条规则。

## 轮播高度真正回弹：把外框比例钉到 embla 根节点

- 现象：只改每张幻灯片自身高度没用——embla 幻灯片是同一行 flex，行高由组内最高的那张决定，组里有一张长竖图时切到横图，下方仍留一大片空白。
- 修法：`WeiboMediaPreview` 用**当前项**（`items[currentIndex].size`）给 `Carousel` 根节点设 `aspect-ratio` + `overflow-hidden`，把溢出的其余幻灯片裁掉；`CarouselContent` 加 `items-start`，防止各项被 stretch 拉齐到最高。
- 校验：`tsc --noEmit`、ESLint 通过。

## 播放器按视频分辨率铺开，混排播放可返回宫格

- `WeiboVideoPlayer` 新增 `aspectRatio`（宽 / 高）：用行内 `style` 覆盖默认的 `aspect-video`，非有限值或非正数回落 16:9；`InlineVideoPlayer` 用 `resolution` 算比例传入，竖屏视频不再塞进 16:9 里左右留大片黑边。纯视频微博与混排播放器共用这条路径。

## 播放器限高 720px

- `WeiboVideoPlayer` 容器加 `max-h-[720px]`：竖屏视频按 `aspectRatio` 铺开会很占版面，超过 720px 后高度被截住，画面由 `video` 的 `object-contain` 居中、左右留黑底，不把卡片撑长。
- 校验：`tsc --noEmit`、ESLint、Prettier 通过。

## 刷新与切页都把内容区滚动条拉回顶部

- 滚动宿主是 `AppContent` 里 ScrollArea 的 viewport（`[data-slot="scroll-area-viewport"]`），外部拿不到 ref，故按 `pageRef` + `querySelector` 找；选择器与回顶动作统一收进 `@shared/utils/scrollArea` 的 `scrollAreaToTop(root)`，找不到宿主静默跳过。
- 顶栏「刷新」（`handleRefresh`，含空态与子组件传下去的同一入口）在发起请求前先回顶；切换导航视图用 `useEffect([view])` 在提交后回顶，覆盖 `WeiboNav` 与账号菜单进「我的赞」等其他入口。
- 校验：`tsc --noEmit`、ESLint、Prettier 通过；`weiboFeed`(11) + `weiboFeedList`(4) 共 15 项通过。

## @账号链接识别加固

- 现象：部分 @账号不生成链接。根因是锚点解析只认 `href`，且属性读取只支持带引号的写法：`javascript:void(0)`、无 `href`、属性无引号三类都会直接降级成纯文本。

## 图床 errno -2：cs 不能随机、通道顺序改为裸字节优先

- 实机回包 `{"ret":false,"errno":-2}`（两种通道一致）说明服务端收到了请求但校验不通过；对照论坛抓包确认该接口设计为「元数据全在 query、body 放裸文件」（`Content-Length` 与 `file_size` 相等、`Content-Type: application/octet-stream`）。
- `cs` 是微博前端 JS 计算的签名参数（每次变化、算法未公开），用两个真实样本枚举 CRC32 / djb2 / Java hashCode / FNV-1a × 字段子集排列 × 分隔符，无一命中，说明带盐，无法离线复现；随机值会被判校验失败，故改为**不传 cs**（`PicUploadQuery.cs` 变可选）。
- 通道顺序改为**原始字节流优先**（裸字节 + `application/octet-stream`），失败再退回 multipart；两次都失败时错误里带通道、uid、字节数。
- 校验：`tsc --noEmit`、ESLint、Prettier 通过；`weiboPublish` 18 项通过。

- 文档 14.18 同步该结论。
- 校验：`tsc --noEmit`、ESLint、Prettier 通过；`weiboPublish` 22 项通过。
