修复：按 `(字号倍数 − 1) × 标题 line-height 1.3 ÷ 2` 逐级下移行号（h5 为 1em 不偏移），用 `em` 表达（1em 即编辑器字号，随字号设置等比缩放）；同时把行号 `font-size` 的兜底值改为与正文同源，保证 em 基准一致。顺带补 `blockquote`（padding-top 0.4em）与 `pre`（padding-top 0.85em、首行 code 0.9em/1.55 行高）的行号 `top`，让行号不再压在 padding 区。

**行内格式**：`toolbar/formatCommands` 提供激活态读取与开关命令；不提供下划线、上标下标、行内代码（前两者 GFM 无语法，写入即变内联 HTML 会整篇只读）。链接输入用 `@components/ui/input-group`，左侧固定 `https://` 前缀（输入自带协议或以 `/ # .` 起头时自动隐藏），回填时剥掉 https 前缀。

**弹出时机**：按住鼠标整个拖选过程都不弹，`pointerup` 后延迟一拍（等 ProseMirror 落地）再结算；键盘扩选走 220ms 尾随防抖，已弹出后 60ms 跟随；锚点取选区末行底边、`side="bottom"`，工具条挂在文字下方。`pointerdown` 时必须同时清掉 `dismissedRef` 与 `lastRangeRef`——拖选期间不排定 refresh，旧范围会一直留到松手，重新选中同一段会被误判成「同一次选区」而拒不弹出。

**关闭判定**：Popover 不用自身 outside-click（块类型与更多菜单是独立 Portal），改为 document pointerdown 捕获 + `data-slot` 归属判断；工具条主体按选区 `from:to` 作 key 重挂载，换选区不残留输入态。

## 追加：取消链接报同步失败、划线消失

**摘链改事务直改**：`removeSelectionLink` 不再走 `focus + setTextSelection + unsetLink`，改为 `tr.removeMark(range, schema.marks.link)`。浮层存活期间文档可能被快照重建，冻结的 from/to 一旦越界，`setTextSelection` 抛 RangeError 会让整条链当场中断；行内命令的 range 现在统一 clamp 进当前文档。摘链只改 mark，`docChanged` 为假时不派发事务；焦点由调用方 `editor.view.focus()` 交回正文。

## 追加：点击已标注文本直接出菜单

**入口**：`pointerup` 结算时若选区仍是塌陷态，用光标位置去命中链接 mark 或划线记录；命中就按该段完整范围调 `openAt(from, to)`，不必先拖选。链接优先于划线。

**命中口径**：链接用「块内双向扫同一枚 mark」——光标常停在字符之间，位置本身与 `pos - 1` 任一被覆盖即算点中，点末尾也能命中；划线用块下标 + 块内偏移落在 `quote` 区间内（末尾位置也收），与装饰层同一套 quote 定位。

**范围即选区**：菜单的 `range` 取标注范围而非光标，所以复制、批注、取消划线、编辑链接全部照常可用，命令按该范围执行。

**防误关**：点击态打开后若有塌陷类 `selectionUpdate`，只要光标还在展示范围内就不关闭；移出范围或在别处点击才关。

**配套**：`SelectionToolbar` 新增 `annotations` prop（`EditorScreen` 传 `useAnnotations().items`），`readTopBlockPos` 支持按位置取块。

**点击态必须用冻结范围**：菜单出现后编辑器里只有塌陷光标，所有写操作都不能再读 `editor.state.selection`——`buildDraft` 读到空范围会直接返回 null，表现就是「菜单点了没反应」。因此 `addOrToggleHighlight` / `applyHighlightColor` / `addNote` 增加 `range` 参数（缺省才回落到选区），`readSelectionLink` 也改为按范围取 mark 的 href（点击停在链接右侧时 `getAttributes` 读不到，会把「移除链接」误置灰）。批注的引用范围由 `EditorScreen` 在打开弹窗时冻结，提交时回传。

**取消划线按 id**：点击命中划线时，`useSelectionToolbar` 把命中的标注记录一并放进快照，工具条据此把「划线」按钮换成「取消划线」（Eraser 图标），直接 `removeAnnotation(id)`，不再依赖「同块 + 同 quote」的文本匹配。链接与划线压在同一段时范围按链接算、划线记录仍带上，两个入口同时可用。

**链接打开方式**：webview 自己的链接处理比页面脚本更早（window 捕获阶段，只认被命中的 `a` 元素），事件层拦不住。最终用 CSS 彻底禁用：`.zhai-editor-content a { pointer-events: none; cursor: text }`，单击根本打不到 `a`，webview 也就不会跳转。Ctrl / Cmd + 点击改用 `editor.view.posAtCoords` 按坐标反查链接 mark 拿地址，再走新增的 `editor/openLink` 协议交给宿主 `vscode.env.openExternal`（`readOpenableUrl` 只放行 http/https/mailto）。Ctrl+点击同时跳过弹菜单（`pointerup` 里判 modifier）。

**回写管线缺 GFM**：`buildEdits` 的 HTML→Markdown 管线只挂了 `rehype-parse + rehype-remark + remark-stringify`，删除线（Strike 渲染成 `<s>`）会转成 mdast `delete` 后字符串化抛 `Cannot handle unknown node 'delete'`，含删除线的段落一编辑就整块回写失败。已补 `remarkGfm`，并在 `editorDocumentSync.test.ts` 增加删除线回归用例。

**裸 URL 自动识别会让取消链接失效**：GFM 的 autolink literal 会把裸地址重新识别成链接，取消链接写回裸地址后下一次快照又变回链接。`readEditorSnapshot` 现在按源片段判断——不以 `[` 或 `<` 起头的 link 一律降级为纯文本，只保留显式写法；已加回归用例。

**链接改动立即落盘**：链接是低频操作，`SelectionToolbar` 增加 `onCommitted`，应用／移除后立刻 `flush()`，不等 500ms 防抖。宿主 `applyChange` 在「区间转换后没有产生写入」时记 warn，便于用「查看日志」区分是 diff 没检测到还是转换失败。

**双击选词**：ProseMirror 默认按空白切分，一整段中文没有空白，双击会一路扩成整段（表现为「全选当前行」）。`editorProps.handleDoubleClick` 改为用 `Intl.Segmenter` 按词边界选中命中片段，不支持时回落到默认。

**浮层结算鲁棒化**：`pointerup` 不再以 `isSelectingRef` 为前置条件（按住标记一旦因异常路径卡住，整场会话都不再弹），改为幂等结算；`openAt` 用 `from:to` 作 key 去重，同一范围重复结算不再重设快照，避免点浮层按钮时忽隐忽现。

**移除「点击标注出菜单」**：按用户要求回归常规操作——只有选中文字才弹。删除 `useSelectionToolbar` 的命中解析（`findLinkRange` / `findHighlightAt` / `resolveAnnotatedHit`）、快照 `annotation` 字段、`SelectionToolbar` 的 `annotations` / `onRemoveHighlight` 与「取消划线」按钮分支、`EditorScreen` 的相关传参。保留：划线按钮 toggle + 色板、链接面板、Ctrl/Cmd+点击打开链接（按坐标识别 mark）、autolink 降级、删除线回写修复、链接后立即 flush。取消划线回到「选中后点划线按钮」的 toggle 语义。

**取消链接按 mark 全长删**：`findLinkRange` 改用 TipTap 的 `getMarkRange` 扫两端，`removeSelectionLink` 再用 mark 的实际两端把传入范围扩一次——只删半截会留下 `[文字](url)` 残迹。

**取消／应用链接都不关浮层**：摘链后这段文字既不是链接也不是划线，浮层一关就再也点不出来（点击落点不再命中任何标注）。改为只收起地址面板，浮层与其冻结范围保留，可继续划线或重新加链接；应用链接同理。

**去掉「同一次选区不再弹」的抑制**：`dismissedRef` 与 `isSameRange` 判断已删除——它依赖拖选期间的 `lastRangeRef`，任何一次漏更新都会让后续选中被判成「本次已关过」而拒不弹出。现在只要选区有 ≥2 个字符就弹；关闭后不会自己重开（没有 selectionUpdate 就不会走 refresh）。`lastRangeRef` 只保留给「点击态塌陷守卫」用。

## 追加：链接命令改纯事务（修「操作后不保存、菜单不弹」）

**根因判断**：`applySelectionLink` 原本走 `chain().focus().setTextSelection(range).setLink()`，点面板按钮时会把焦点抢回正文、把选区从冻结范围上挪走；`removeSelectionLink` 之前还额外 `editor.view.focus()`。两者都在「浮层仍开着」的前提下改选区/焦点，后续 `refresh` 对不上范围，表现为后续选中不再弹菜单，回写链路也随之错位。

**改法**：两条链接命令都改成纯事务——`tr.removeMark(range)` + `tr.addMark(range, linkMark)`，不 focus、不动选区；添加前先删同范围旧链接，避免 `addMark` 叠加出两条 link mark。焦点留在面板按钮上，用户点正文才落光标。

**快照自愈**：`useEditorDocument.flush` 在 `pathRef` 为空时不再静默返回，改为补拉一次快照（`recoveryRef` 闸门只放行一次），修掉「首次快照没拿到 → 怎么改都不保存且一声不响」。

**只读必须可见**：日志里完全没有 `回写未产生写入` / `编辑器请求失败`，说明 `flush` 根本没走到回写——最可能是 `editor.isEditable === false`（只读文档下 `runAtRange` / `removeSelectionLink` / `flush` 都会静默早退）。现在链接应用/移除、划线、选色前都会先判可编辑并提示「当前文档为只读，改动不会写回」，`flush` 的只读分支也会弹一次同类提示（同 id 去重）。

**只读常驻条 + 原因**：toast 只在「变为只读」时弹一次，用户很容易错过，事后只剩「编辑器坏了」的观感。改为 `.zhai-editor-readonly` 顶部常驻条，并让 `readEditorSnapshot` 收集 `unsupportedTypes`（白名单外节点类型，去重后随快照下发）拼进文案，用户能直接看到是哪类语法触发了整篇只读。`editor.setEditable` 全仓只有 `applySnapshot` 一处调用，`isEditable` 完全由 `snapshot.editable` 决定。

**flush 返回是否落盘**：`useEditorDocument.flush` 改为 `Promise<boolean>`（无变化 / 只读 / path 为空 / stale / rejected / 异常都是 false），链接操作后 `onCommitted` 据此提示「改动未写入文档」。

**落盘交给 VSCode 的 autoSave**：曾试过在 `applyChange` 成功后主动 `document.save()`，结果每次编辑都写盘、刷屏，用户要求「按 VSCode 的自动保存机制来」。已回滚：回写只把改动写进 TextDocument 并置脏，由 `files.autoSave`（afterDelay / onFocusChange / off）决定何时落盘。**不再由扩展代劳保存**——`off` 时文档保持未保存是 VSCode 的正常语义。

**applyEdit 失败不再静默**：`editorProvider.applyChange` 里 `!isApplied` 分支此前既不打日志也不告知前端（返回 `stale: false` 且无 rejected），前端当成成功——表现就是「链接变蓝、无提示、文件没变」。现在该分支记 `回写被编辑器拒绝：<路径>（N 个区间，version X）` 并返回 `failed: true`，`EditorChangeResult` 增加可选 `failed`，前端统一提示「改动未能写入文件」。划线走的是标注 API（不写文档），所以「划线可以」不能证明保存正常——必须看这个提示。

**链接写入必须可观测**：`applySelectionLink` / `removeSelectionLink` 改为返回 boolean，UI 层失败时 toast（未选中文字、未启用链接、写入失败）；`applySelectionLink` 不判 `docChanged`——重复应用同一地址时终态与原文档一致，但 mark 已就位，不能算失败。已确认 StarterKit 内置 Link（`if (this.options.link !== false) extensions.push(Link.configure(...))`），`schema.marks.link` 存在。

**删除块级只读设定**：整篇白名单判定是「链接/划线/回车全失效」的根源。按用户要求移除——删 `EDITABLE_NODE_TYPES`、`isSupported`、源码块降级、`applyChange` 的写入前自检 rejected、前端只读提示与常驻条、`unsupportedTypes` 字段；`readEditorSnapshot` 恒返回 `editable: true`（字段保留只为兼容协议）。代价：内联 HTML、脚注、带对齐表格、嵌套任务列表在编辑保存后可能被改写，因为 TipTap schema 不认识它们。原「表格对齐/任务项嵌套判只读」两条测试改为期待可编辑。

## 追加：选区工具条系统性审查与修复

**划线改色误删（critical）**：`addOrToggleHighlight` 是 toggle 语义（同块 + 同 quote 命中即删，不比较颜色），而色板选色复用了同一入口——"点划线落笔 → 选色改色"第二次调用必然命中删除分支，把刚划的线抹掉。改为**落笔与改色分开**：`useAnnotations` 新增 `applyHighlightColor`，同位置已有划线走 `editor/annotation/update` 的 `color` 增量更新（宿主侧早已支持），没有才 `add`；颜色相同直接短路。工具条侧 `handleToggleHighlight` 与 `handlePickColor` 拆开，后者先等前一次落笔 Promise 结束再改色，避免 `items` 未刷新时把改色走成再新建一条。

**Esc 冒泡（critical）**：链接输入框的 Esc 只 `preventDefault()` 没有 `stopPropagation()`，事件一路传到 window 被 `useSelectionToolbar` 当成关闭整个浮层，且 `dismissedRef` 置位后同选区不再自动弹出。Esc 分支补 `stopPropagation()`，Enter 分支加 `return` 与 Escape 互斥。

**`hasLink` 绑错数据源（critical）**：`hasLink` 原来传 `linkValue.length > 0`（输入框草稿），与"选区是否已有链接"无关——清空输入框后「移除链接」变灰无法摘链，无链接时敲字反而出现移除入口。改为打开面板时读一次 `readSelectionLink` 存入 `hasExistingLink`。

**复制链路**：提示计时器改由 `copyTimerRef` 持有，连点先清旧计时、卸载时清理；复制失败从静默改为 `toast.error`。

**关闭态监听**：`document` 的 pointerdown 捕获监听从"挂载即注册"改为 `isOpen` 为真时才注册，避免浮层关闭时每次点击正文都触发一次 `dismiss()` 的无效状态更新与重渲染。

**防御与可访问性**：划线 Promise 补 `.catch()` 兜住未处理拒绝；链接输入加 `maxLength=2048`；应用按钮补 `aria-label`/`tooltip`；「取消链接」文案改为符合实际行为的「移除链接」。

**方案取舍记录**：并发 toggle 防抖（pending ref）未实施——会吞掉用户"划线再点一下取消"的连续操作，属行为变更，需单独确认。
