## 编辑区全链路保存策略审查与修复

用户反馈：改动后文档保存不了，菜单与其它动作也无法操作。按「webview 采集 → 协议 → 宿主转换 → applyEdit → 回声推送」逐环审查，定位到以下失效点。

**回写并发的 stale 回滚（critical）**：`flush` 没有在途保护，防抖计时器、`visibilitychange`、浮层提交三条路径会同时发出带同一 `version` 的请求，宿主对第二条必然回 `stale`，前端随即整篇 `loadSnapshot(true)` 重载——用户刚敲的内容当场被宿主版本盖掉，观感就是「改了保存不了」。改为串行队列：在途期间置 `pendingRef`，结束后补跑一轮，最后一段输入不会丢。

**零写入被当成成功（critical）**：宿主 `buildEdits` 丢弃区间（越界、重叠、合并单元格、整块转换失败）时返回 `appliedBlocks: 0` 且不带 `failed`，前端把它当成功继续刷新 baseline，下一轮又算出同一批无效区间，如此循环——磁盘上永远没变，屏幕上没有任何提示。宿主改为返回 `discarded`（被丢弃区间数），前端在 `appliedBlocks === 0` 时提示「改动未能写入磁盘」并且**不刷新 baseline**，保留本地基准让下一轮重试。

**baseline 采样时机（高）**：原实现把 `pairBaseline` 放在 `requestAnimationFrame` 里，webview 不可见时 rAF 不执行，baseline 会一直为空数组，之后第一次回写就把整篇当成新增内容全量替换。`setContent` 是同步事务、`DOMSerializer` 也不依赖渲染，改为同步采样并去掉 rAF。

**回声推送时序（高）**：`appliedVersions` 只在 `applyEdit` 之后记录，`onDidChangeTextDocument` 若在回执前到达就会漏判，多推一次快照使前端 `setContent` 整篇重建（选区丢失、正在操作的浮层与菜单被打断）。改为双保险：执行前记录预期版本 + `applying` 集合标记在途，事件侧按 `applying` 与版本区间双重跳过。

**快照缺失静默（中）**：路径为空时旧实现只补拉一次（`recoveryRef` 一次性闸门），第一次失败后整场会话都不再重试且不提示。改为 2s 最小间隔持续重试，仍为空则提示「尚未取到文档快照」。

**stale 静默回滚（中）**：放弃本地改动时补 `toast.warning`，让用户知道输入被外部版本取代。

**显式保存缺失（高）**：常规回写只把改动写进 TextDocument 并置脏，落盘依赖 `files.autoSave`；webview 内没有 VSCode 的保存命令，关掉 autoSave 的用户根本没有落盘入口。新增 `editor/save` 协议 + `Ctrl/Cmd+S` 接管：先 `flush` 再 `document.save()`，失败统一提示。

**浮层内嵌菜单的模态冲突（critical，对应「菜单无法操作」）**：选区工具条是 Radix Popover，新加的块类型菜单与「更多」菜单是 DropdownMenu，默认 `modal` 会在 `body` 上挂 `pointer-events: none` 并抢焦点，嵌套在浮层里时浮层内外一起点不动。两个菜单显式 `modal={false}`。

**遗留风险（本次未改，需后续处理）**：`pairBaseline` 仍按「下标」把编辑器块与宿主快照块配对。TipTap 丢弃或合并自己不识别的块（脚注、HTML 块、复杂嵌套）后两边块数不再相等，偏移会整体错位。彻底解法是让宿主在快照块 HTML 上带稳定 `id`（UniqueID 只补缺失值、不会覆盖），前端按 id 建偏移映射，未匹配块再按相邻锚点推导；这会改动 `EditorBlock` 契约与 blockDiff，单独立项。

## 追加：按参考图改为硬边斜切

参考图是实心矩形 + 两端硬边斜切，不是渐隐。改为单层 `linear-gradient(102deg, ...)`：两端色标直接相邻、不留过渡段，切口宽度 4px / 3px，倾斜约 12°；笔身覆盖 84% 字面高度并略偏下；圆角只收 3–7px。原先「两层不同高度 + 渐隐」的做法整体撤掉，`soft` 中间色不再需要。

**毛刺与对齐**：渐变硬色标切换没有抗锯齿，落在非整数像素上会抖出一排锯齿，两端改为 `3px → 3.8px` 的 0.8px 过渡带；垂直尺寸从百分比换成 em 长度——inline 元素的百分比相对 content area（含 ascent/descent），不同字体下那段空白不同宽，永远对不齐字面。现为 `background-position: 0 0.14em` 顶贴字面上沿、`background-size: 100% calc(1em + 2px)` 让底边出血 2px。

**右侧起伏（两版都不可用）**：先是叠一条「只占下半部 34%」的低浓度短层，出现可见深浅分层——叠加深色做形状本身就走不通，撤掉；再试整条笔触用一条内联 SVG 路径（比例缩放），短划线起伏只有 1px、长段落右端能缺掉 30px，幅度不可控。

**右端起笔点**：渐变做不出「从右上角顶点起笔」的斜边——色标位置按渐变轴投影算，斜线落在哪个角、从哪一行开始都随宽高漂移，顶点处常留一截直边。右端改回 SVG 路径（固定 22px 宽，`M0 0 L22 0 L11 100 L0 100 Z`）：顶点 (22,0) 到 (11,100)，斜边由浏览器抗锯齿，左端仍用渐变。

**角度与起伏**：底边从 11 收到 13（26° → 22°），斜边拆成三段贝塞尔，每段留 0.5~1px 的进出，边缘因此不是一条直尺线。随后按反馈把进出加大到 2~2.5px（控制点 `18.8/21.5`、`16/20.4`）：再小会被看成直尺线，再大就成了锯齿。

**接缝白线**：两层背景相接时各有一条半像素抗锯齿带，只重叠 1px 时两条淡边正好拼成一条白竖线。笔锋层加到 `23px`（path 与 viewBox 同步 +1），主体仍是 `max(calc(100% - 21px), 0px)`，重叠变成 2px，接缝被实色盖住。

**改为遮罩（颜色与形状分离）**：两层同色背景无论怎么拼都有取舍——重叠则半透明叠加变深，不重叠则两条抗锯齿淡边拼成白线。改为单层 `background-color` 上色，形状全部交给 `mask-image`：左段 102deg 硬边渐变、右段 23px SVG 路径，两段故意重叠 1px。遮罩是取并集（默认 `source-over` / `add`），重叠既不变深也不露缝。

**配色与顺序**：`HIGHLIGHT_STYLES` 按字母序书写，色值换成明度更高的荧光笔取向（黄 255,226,122 / 蓝 133,189,255 / 粉珊瑚 255,150,160 / 绿 137,226,160 / 紫 199,160,255）；`SelectionToolbar` 的 `SWATCH_COLORS` 与 `HIGHLIGHT_COLORS` 同步，保持「点选的颜色」与「落下的颜色」一致。

**mask 会裁到文字（critical）**：遮罩作用于元素的全部内容，不只背景——斜切与起伏的边缘会把同一段文字一起裁掉，表现就是「划线后字变细、变样」。装饰层改为只用 `background-image`（一条 SVG 路径画完整笔触），同时去掉横向 padding（会撑开行内盒改变字距）。代价是端部斜切改按宽度百分比走，不再固定像素。

**字重被压成 300（critical，真凶）**：`globals.css` 里有 `* { @apply ... font-light }`，Decoration 生成的 span 会命中它，把从 h1–h6 / strong 继承的 600 压成 300——表现为「划线后标题/加粗被取消」。修法是在装饰 style 里显式写 `font: inherit`（inline style 优先级高于 `*`），字号、字重、字体族一并跟随父级。

**最终笔触（恢复固定像素端部）**：主体渐变（左端 102deg 斜切）+ 24px 固定宽笔锋（顶点起笔、三段贝塞尔起伏）。两层不再硬拼接：主体右端 5px 淡出、笔锋左端 5px 淡入（SVG `linearGradient` 以 `userSpaceOnUse` 固定 5px），交叉后合成浓度与两侧差 < 2%，既无白线也无深线。

## 追加：图片样式被内联样式压住

`editor.css` 的 `img` 规则不生效，根因是 `ZhaiImage` 的 nodeView 给 `<img>` 写了 `style.cssText`（`max-width/height/border-radius/display/margin`），内联样式优先级最高，CSS 怎么改都被压住，只能靠 `!important` 顶回来。改为 nodeView 不再写内联样式，尺寸、留白、圆角统一由 `editor.css` 的 `img` 规则提供（`display: block` 从内联迁到 CSS），渲染态与编辑态因此完全一致，调试用的 `!important` 一并去掉。

## 追加：表格样式重做

原来编辑态是整格 1px 网格、渲染态又是另一套（border + 斑马纹），两处观感不一致，网格感偏重。改为共用一套视觉：外框一条细线 + `border-radius: 0.55em`，单元格只留横线（竖线交给外框），表头铺浮层色并加一条 18% 前景色底线，斑马纹 4%、悬停 6%（`color-mix` 前景色叠加，深浅主题自动相反）。圆角只能落在四个角单元格上——`table` 自身的圆角裁不掉单元格底色；`border-collapse` 从 `collapse` 改为 `separate` + `border-spacing: 0`，否则外框与内线会合并成双线。编辑态只保留 TableKit 需要的 `table-layout: fixed`、`min-width` 与选中框定位，渲染态只保留滚动布局。

## 追加：表格工具改为悬停显示、正文底部空白可续行

**表格工具触发条件**：原实现只在 `editor.isActive('table')`（光标在表内）时渲染，鼠标扫过表格什么也没有。改为在 `.zhai-editor-page` 上监听 `pointermove`，命中 `table` 即记为该表格；指针落在工具条自身（新增 `data-table-tools` 标记）上时保持不清，否则移到按钮上就消失、根本点不到；指针离开编辑区清空。显示目标取「悬停表格优先，光标所在表格兜底」，只读态仍不渲染。

**悬停表格与光标表格不同源**：加行 / 加列 / 菜单命令都依赖光标所在行列，鼠标悬停在另一张表上直接执行会作用到错误表格。`tableActions` 新增 `findActiveTable`（从 `TableTools` 迁入）与 `focusTable`：用 `view.posAtDOM(table, 0)` + `TextSelection.near` 把光标先落进目标表格，已在该表内则保持当前单元格不动。`appendTableRow/appendTableColumn` 的 `table` 参数可选，省略时沿用旧行为（键盘与内部调用）。

**菜单打开期间冻结目标**：Radix 菜单渲染在 portal 里，页面收不到 pointermove，重算会让按钮随指针抖动；开合状态走 ref 给事件监听读，打开期间跳过悬停更新，关闭时清空悬停目标（此时指针停在已消失的菜单上，留着会把按钮钉在旧表格）。

**正文底部空白续行**：文档末尾就是编辑区底部，最后一行下方那截空白点不进去（末块若是表格 / 图片更彻底无解）。`editor.css` 给 `.zhai-editor-content` 加 `padding-bottom: 8rem` 作为「可写的额外行」；`EditorScreen` 在 `.zhai-editor-page` 上用 `onMouseDownCapture` 接管落在空白容器本身（正文元素 / 页面容器 / `.zhai-editor-scroll`）且低于最后一个块底部的按下：末块已是空段落就只落光标，否则 `insertContentAt(end, { type: 'paragraph' })` + `setTextSelection(end + 1)` 并 `scrollIntoView`。必须 `preventDefault`，否则 ProseMirror 之后还会按坐标把光标贴回最后一块。捕获阶段执行早于 ProseMirror 在正文元素上的原生监听，浮动工具的点击命中它们自身元素，不受影响。

## 追加：修复加号按钮点不到

现象：悬停显示后鼠标移向加号，按钮当场消失，点不下去。

**根因**：按钮与表格之间隔着一段「不属于任何元素」的距离——表格自带 `margin: 0 0 1em`，两个加号又各带 `mt-1 / ml-1`。指针从末行 / 末列滑向按钮时先落在这段空隙上，`pointermove` 的 target 是正文容器，原实现当场 `setHover(null)`，按钮在鼠标到达之前就被卸载（mousedown 与 mouseup 落在不同元素上，click 也不会产生）。

**修法**：清空改为宽限计时（`HOVER_CLEAR_DELAY = 600ms`）——命中表格或工具条时 `cancelClear`，落到其它位置只 `scheduleClear`；指针离开编辑区仍立即清空。宽限到期时用最近一次指针坐标做 `document.elementFromPoint` 复查，命中表格或工具条就不清空，防止中途移动事件被浮层吃掉后误判断。

**没改样式**：`mt-1 / ml-1`、等宽 / 等高、`variant` 都由用户定，缝隙用事件侧兜住而不是靠挤掉间距。

## 追加：块把手「插入表情」失效 + 表情面板高度溢出

**失效根因**：表达式面板是在 `SLASH_COMMANDS` 的 emoji 项里打开的（`openEmojiPicker`），而块把手的**插入菜单**（`BlockHandle` 里的 DropdownMenu）没处理 `onCloseAutoFocus`——Radix 菜单关闭时默认把焦点还给触发按钮，正文随即失焦，刚挂载的表情 Popover 收到 focus outside 后当场关闭，表现为「点了没反应」。`BlockMenu` 早已有这层处理（preventDefault + `editor.chain().focus()`），插入菜单漏了；此前插入菜单里全是即时改文档的命令，焦点被抢无感，加上需要长驻的浮层就暴露了。修法两处：插入菜单 Content 补 `onCloseAutoFocus` 由编辑器接管焦点；`EmojiPicker` 的 PopoverContent 加 `onFocusOutside` preventDefault（点击外部仍由 pointerdown outside 关闭）。

**高度溢出根因**：`ScrollArea` 的 Root 是 `relative`、Viewport 是 `size-full`，只给 `max-h-56` 时父级高度由内容撑开、被 max-h 截断，而 Viewport 的 `height: 100%` 在父级高度 auto 时无法解析，滚动条不出现、内容直接溢出面板。改为给 ScrollArea 确定高度 `h-56`，Viewport 拿到 224px 后内部滚动生效；空结果提示移进 ScrollArea 内，面板高度恒定。另给 PopoverContent 加 `collisionPadding={8}`，避免贴视口边缘。
