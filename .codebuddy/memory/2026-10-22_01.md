## 修复：全站滚动条统一 + 模型菜单下半截发透

### 变更

- `globals.css` 增加 `* { scrollbar-width: thin; scrollbar-color: var(--scrollbar-thumb, ...) transparent }`，作为主方案（新版 Chromium 在 Windows 走 Fluent 标准滚动条，忽略 `::-webkit-scrollbar`），WebKit 伪元素规则保留给旧引擎；并补 `.no-scrollbar` 定义（此前类名被使用但项目内无定义，统一后会冒出滚动条）。
- `AiChatModelMenu` 把限高与滚动从 `DropdownMenuContent` 移到内层 `div`：外层不滚动，`before` 伪元素的毛玻璃底色与描边才不会随内容滚出可视区。
  - 根因：`DropdownMenuContent` 的底色由 `before:absolute inset-0` 伪元素 + `bg-popover/70` 提供，伪元素位于滚动内容层，滚动后其下半部移出视口，故底部发透。

### 验证

- `tsc --noEmit`、`eslint src --max-warnings=0`：通过。
- `vite build`：成功，产物 CSS 含 `scrollbar-width:thin`（2 处）与 `.no-scrollbar`（4 处）。

## 修复：模型菜单出现水平滚动条

- 根因：`DropdownMenuSeparator` 带 `-mx-1`（左右各 -4px），原结构靠 `DropdownMenuContent` 的 `p-1` 抵消；滚动容器下沉到内层后内层无 padding，分隔线比容器宽 8px。CSS 规范中 `overflow-y: auto` 会把 `overflow-x: visible` 计算为 `auto`，溢出即表现为水平滚动条。
- 修复：内层滚动容器补 `overflow-x-hidden`，裁掉这 8px。
- 验证：`tsc --noEmit`、`eslint src --max-warnings=0` 通过；`vite build` 1.75s 成功。
