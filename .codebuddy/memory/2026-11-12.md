## 修改内容摘要

修复 AI 对话在「切到其他模块页面再回来」后的状态失联：生成任务本由宿主 `AiChatService` 单例推进、与页面生命周期无关，但页面卸载后增量订阅解除，重进时 `phase` 从本地初值 `idle` 起算，导致占位态残留、无停止入口、发送被宿主拒绝、流末结果不回显。

`useAiChatSession` 三处调整：

1. `loadSession` 接管在途流：新增私有函数 `readInFlightMessageId(snapshot)` 取快照中最后一条 `pending` / `streaming` 的助手消息 id（压缩系统消息可能排在生成中的助手消息之后，故取最后命中项而非末条消息）；仅在本地无在途锚点（`streamingMessageIdRef` 为空）时写入锚点并用函数式 `setPhase` 把 `idle` 提升为 `streaming`，不覆盖 `sending` 等本地更权威的阶段。
2. 流末兜底：`onStream` 的 `done` 事件在无锚点时改为回拉 `loadSession()` 补齐结果（原实现直接 return，重进后内容永远停在占位态）；effect 依赖补 `loadSession`。
3. `stop` 自愈：读取 `ai/abort` 回包，`aborted !== true` 表示宿主已无在途请求（接管到的可能是崩溃残留占位），就地清锚点并复位 `idle`，避免发送被永久拦住。

文件头「关键约束」同步补充「生成由宿主推进、与页面生命周期无关」与接管策略。

## 追加：跨作用域切换文档时的在途生成对账

切换编辑区文件不触发宿主中断（`AiChatService` 只在 `dispose` / `deleteSession` / `ai/abort` / 空闲超时时 abort）。同一作品或同一公众号内切文件时，对话页 key（作品目录 / 模块目录）不变、组件不重建，连增量都不受影响；但切到另一个作品、非作品文档或公众号时作用域变化，对话页重建且宿主活跃会话换成新作用域那份记录，旧会话的在途生成仍在后台跑完并落到旧会话——此前这条路径既看不到进度也无法停止（`phase` 初值 `idle`，Composer 不显示停止按钮，发送又被宿主以「已有生成中的回复」拒绝）。

`useAiChatSession` 对账逻辑重写：

1. `readInFlight()` 改为无参，只做字段收窄（会话 / 消息 id 缺一即视为无效），会话归属判断上移到 `loadSession`。
2. `loadSession` 对账三分支：快照属于本会话且消息 id 对得上的 pending 消息 → 补挂锚点 + 回填；属于别的会话 → 仅 `setPhase('streaming')` 放出停止入口（`phase` 只在 `sending` 时驱动「正在准备上下文…」占位，不会误加消息占位）；无在途请求 → 本地若停在 streaming 就复位 `idle`。仅在 `streamingMessageIdRef` 为空且 `phaseRef !== 'sending'` 时对账。
3. `done` 且无锚点：除了回拉快照，还复位 `phase` / `activeTool` / `transientNotice`，避免别处生成结束后残留生成中态把发送拦住。
4. `send` 失败：错误原因可能是宿主仍有在途生成，失败后补一次 `loadSession()` 把停止入口恢复出来；`send` 依赖补 `loadSession`。

## 追加：生图切页对账与按作用域取消

出图是宿主单例任务（`ImageGenerateService` 的 `activeRequest` 锁），切分区 / 切作品只卸载媒体页、请求继续跑；但页面重建后 `isGenerating` / `stage` 从初始值起算，界面失去骨架与取消入口，且新页面发送撞锁时会在 catch 里调用无归属的 abort，把上一次作品的请求误杀。

1. 类型：新增 `ImageGenerateState`（`generating` / `dirPath` / `stage`）；`HostMethodName` 增加 `pressAi/generateImage/state`。
2. 宿主：`activeRequest` 由 `AbortController` 改为 `{ controller, dirPath, stage }`；`router.generate` 的 `onProgress` 包装后把 stage 记进快照（仍原样转发）；`finally` 改为按 controller 比对释放锁，顺带修掉「取消后立刻重发时旧请求清掉新锁」的竞态；`abort(dirPath?)` 只在 `activeRequest.dirPath` 与入参一致时取消，缺省不校验；新增 `getGeneratingState()`，无在途请求时三项全 null/false。
3. `pressRoutes`：新增 `pressAi/generateImage/state` 路由，`abort` 改走 `readAbortScope(payload)`——payload 带 `dirPath` 字段才校验（字符串为作品目录、null 为通用素材），未带字段或取值非法回落「不校验」以保持旧语义。
4. 前端 `useImageComposer`：挂载（及 dirPath 变化）时查询 state，`generationRef.current === 0` 且作用域一致才认领，恢复 `isGenerating` 与阶段文案；接管态每 `GENERATE_POLL_MS`（3 秒）轮询 state，`generating` 转 false 时复位并 `onLateGenerated()` 静默刷新列表；`abortGeneration` 一律带 `dirPath`；`runSend` / `runAbort` 清 `adoptedRef` 退出接管态。

已知限制：接管态拿不到出图回执，结束后只能静默刷新列表，不会自动认领角色封面。

## 追加：全链路核对——工作流菜单必须跟随当前文档

**机制一：监听即时化**。删掉 `SCENE_DEBOUNCE_MS` 与 `debounceTimer`，`onDidChangeActiveTextEditor` 直接 `refresh()`。去抖原本是为了合并「同一事实的多次事件」，而这已由 `isSameAsLast` 完成；保留去抖的后果是任何走编辑器事件的路径（编辑器内切 tab、资源管理器打开、命令面板新建笔记）都要等 800ms，跨归属切换时表现为菜单不跟随。

**机制二：模块选定带文档锚点**。`selectedModule` 新增 `selectedModuleDoc`（选定当时的活跃文档键），`buildContext` 每次推导先 `dropStaleSelectedModule()`：活跃文档与锚点不一致即清空选定。这样「仪表盘进入公众号页 → 组六分区」仍然成立（未切文档），而用户随后打开作品/笔记时，残留的 `wechat` 选定不会再压住当前文档归属（此前 `readContentScope` 里 `selectedModule === 'wechat'` 排在 `projectDir` 之前，正是「打开作品菜单还停在公众号」的原因）。`selectProject` / `clearProject` 入口同样先做该清理。

**逐入口显式同步**（`syncFromEditor()`，幂等、事实未变时被抑制）：

| 入口 | 落点 | 处理 |
|------|------|------|
| 编辑器内切换 / 资源管理器打开 | VSCode 事件 | 立即 refresh |
