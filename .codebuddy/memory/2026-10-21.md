## 人物设定页 UI 重排：标题 + 新增、定位筛选 + 搜索、卡片网格、下钻详情、新增弹窗

### 变更

- 移除人物页顶部步骤条 `PressFlowSteps`，页面 props 同步去掉 `onSelectStep`，工作流页不再传该参数（设定页、大纲页的步骤条保留）。
- 页头改为三段：标题行（副标题合并人数与说明 + 右侧「新增」按钮）、分隔线、工具行（定位筛选项 + 搜索框）、分隔线。
- 定位筛选复用 `ui/toggle-group`（与大纲树状态筛选同款），搜索框从列表组件上移到页面层；两者状态由页面持有，列表只接收已收敛结果。
- 人物列表由「左窄列表 + 右详情」改为响应式卡片网格（1 / `@md` 2 / `@3xl` 3 列），卡片复用 `ui/card`，展示姓名、定位徽标、身份与核心欲望摘要。
- 详情改为整页下钻：选中卡片即铺满内容区，返回按钮不再随宽度隐藏；选中项失效（人物被删除）自动回列表，不渲染空详情。
- 新增人物改走 `ui/dialog`（新文件 `CharacterCreateDialog`），只收姓名（必填）、定位、身份、别名四项；姓名为空禁用创建按钮；`key` 绑定展开状态重建表单，不写重置副作用。
- 空态区分「一个人都没有」（提供新增按钮）与「没有匹配」（提供清空筛选）。
- 建卡链路由 `onCreateCharacter` 回传新卡 id，页面据此直接进入新卡详情；`createCharacterCard` 支持 `seed` 初始值，id 仍由 utils 生成。
- `constants` 新增 `CHARACTER_ROLE_ORDER`（排序与定位选项共用）与 `CHARACTER_ROLE_FILTERS`（筛选 tab）；`types` 新增 `CharacterSeed`（不含 id 的初始值）。

### 依据

- 用户确认 UI 结构（标题 + 新增 / 筛选 + 搜索 / 分隔线 / 卡片列表）与「新增用 dialog」。
- 用户选定决策 A：详情走整页下钻，卡片承载三行摘要；不把 tabs 表单塞进 dialog，避免双层滚动。

## 人物编辑 dialog 化 + 外貌字段与 AI 生成

### 变更

- 人物编辑改为弹窗：新增 `CharacterEditDialog`（dialog 壳 + 取消 / 保存），`CharacterDetail` 降级为弹窗内表单体，去掉返回按钮与内部标题行；草稿模式——弹窗内改动只进本地草稿，保存才回写人物卡，取消或关闭一律丢弃。
- 列表不再下钻：`PressCharacterPage` 删除 `selectedCharacter` 分支与详情区，改为 `editingId`；卡片点击直接开编辑弹窗，列表常驻；卡片去掉选中态与 `selectedId` 入参。
- 人物卡新增 `appearance` 字段（`CharacterCard` / `createCharacterCard` / 示例数据同步），编辑弹窗新增独立「外貌」tab（第 5 个），内含 Textarea、AI 生成按钮、生成中「取消」与错误行内 Alert。
- AI 生成链路为 press 模块首个宿主直连能力：新增 `pressAi/aiAppearance` 与 `pressAi/aiAppearance/abort` 两条协议，前缀刻意与仪表盘作品协议 `press/*` 区分；`aiChatProvider` 增前缀分支并注入 `PressRoutes`。
- 宿主新增 `modules/press/ai/appearancePrompt.ts`（系统提示 + 用户提示 + 输出清洗：去围栏 / 标题 / 列表符号 / 首尾引号，超 600 字截断）、`aiAppearanceGenerator.ts`（streamChat 聚合，temp 0.9、maxTokens 500、60s 超时）、`pressAiService.ts`（入参收窄、密钥校验、配额、并发锁与取消）、`pressRoutes.ts`、`db/connection.ts`（独立 press.db，只建 meta 表）。
- 配额独立：新增配置 `zhai.press.aiDailyLimit`（默认 20，≤0 不限），计数键 `press_ai_date` / `press_ai_count` 存在 press.db 的 meta 表，不与取名配额共用。
- 前端新增 `useCharacterAppearance` hook（70s 超时、错误归一、卸载时取消在途请求），外貌上下文取作品的 `era` / `genres` / `tone`，由 `PressCharacterPage` 经 `setting` 入参下传。

### 依据

- 用户确认三项决策：外貌独立 tab、生成结果写入草稿可编辑、配额独立不共用取名额度；不做「补充要求」输入框。
- 生成结果不直接落库，避免弹窗内的 AI 输出绕过用户确认。
