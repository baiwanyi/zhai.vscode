- 根因：`@webview/components/Button` 的加载态把 children 整个换成 Spinner，按钮宽度随文本消失而塌缩；页脚是 `justify-between` 两端布局，主按钮一缩，右侧按钮组整体左移/主按钮左边界移动，视觉上即抖动。

## 复核（结论：无需修改）：shadcn switch 的 data-checked / data-unchecked

- 曾误判：以为 `radix-ui@1.8.1` 只输出 `data-state`（checked / unchecked），不写 `data-checked` / `data-unchecked`，故 shadcn switch 的选中配色与滑块位移会失效。

## 修复：校对问题条目二次超宽（clamp 才是真凶）

- 机制：Tailwind 的 `line-clamp-N` 生成 `overflow:hidden + display:-webkit-box + -webkit-line-clamp`。`-webkit-box` 下内部 flex 子项不再按 flex 规则参与排版，`truncate` / `shrink-0` 失效，文本按 max-content 单行铺开，再由 `overflow:hidden` 裁掉——视觉上就是「文本超宽被切」。
- 上一轮只改了理由行，`ItemTitle` 的 `line-clamp-1` 仍在，所以原文行与建议行继续超宽；`line-clamp-none` 只用于让 `cn` 挤掉默认的 clamp 类（v4 的 line-clamp utility 只按数字 bare value 生成）。
- 最终改法：`Item` 加 `flex-nowrap`；`ItemTitle` 写 `line-clamp-none` 退出 clamp，改为 `flex + overflow-hidden`，原文与建议两个 span 都 `min-w-0 truncate`；理由改用普通 `<p className="w-full … wrap-break-word">`，完全不依赖 ItemDescription。

## 修复：滚动容器把整页内容撑宽（超宽真凶）

- 根因：Radix ScrollArea 的 Viewport 内部会插一层 `div[style="min-width:100%;display:table"]`（见 `@radix-ui/react-scroll-area` dist 第 199-210 行，用于测量横向溢出）。`display: table` 按内容的最小宽度取列宽，后代只要出现较宽的不可断内容，整页内容区就被撑宽；而 ScrollArea 未启用横向滚动条时 `overflow-x: hidden`（dist 第 151 行），超出的部分直接裁掉，表现就是「文本没有换行、一直向右被切」。
- 修复：`AppPage.tsx` 的 `AppContent`（isScrollable 分支）在 ScrollArea 上加 `[&_[data-radix-scroll-area-viewport]>div]:block`，把内容壳退回 block，宽度只跟视口走；内层内容 div 补 `w-full`。
- 影响面：全站使用 `AppContent isScrollable` 的页面都不再有横向撑宽；依赖横向滚动的内容后续需要单独加局部 ScrollArea。

## 修复：滚动容器宽度覆盖未生效（内联样式优先级）
