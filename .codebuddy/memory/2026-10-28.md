## 修复：提示词词条区出现横向滚动条

- 根因：词条网格用 `overflow-y-auto`，按规范 overflow-x 会被提升为 auto，任何向右越界的子元素都会带出横向滚动条；而每个词条单元格里的编辑 / 删除按钮组用 `absolute -right-1`（右边缘外凸 4px），最右列的格子右边界正好贴着网格内容盒右边界，这 4px 就是唯一越界量。
- 修复：按钮组定位由 `-right-1` 改为 `right-0`，右边缘对齐格子边界、不再外凸（上沿的 `-top-1.5` 保留，属设计意图）。只修这一个根因，不靠 `overflow-x-hidden` 掩盖——网格内除该按钮组外没有可越界元素：列是 `minmax(0,1fr)` 且格子 `min-w-0`，按钮 `w-full`、文本 `truncate` 都已约束在列宽内。
- 排查手段：需确认是否还有其它越界元素时，在 webview DevTools 对网格容器跑 `clientWidth/scrollWidth` 与后代 `getBoundingClientRect().right` 的差值比对，不靠肉眼或截图推断。
- 验证（逐项）：`pnpm exec eslint src/workflow/imagegen/layout/ImagePromptPicker.tsx` 0 告警；编辑器诊断 0 条。

## 优化：词条编辑 / 删除覆盖层补底色与左侧渐变

- 背景需求：覆盖层直接压在词条文字上会出现硬边，且两个 ghost 按钮之间的缝隙会透出下层文字。给容器按词条按钮的 variant 上底（未选中 `bg-background` / 悬停 `bg-muted`；选中 `bg-secondary` / 悬停 `color-mix(in oklch,var(--secondary),var(--foreground) 5%)`），并加 `rounded-xs` 收掉直角。
- 渐变：容器左侧外挂一个 `absolute inset-y-0 -left-4 w-4` 的 `aria-hidden` 层，`bg-linear-to-r from-transparent`，终点色与容器底色同步（含 group-hover 态），让被遮住的词条名淡出到底色而不是被硬切。
- 关键约束：底色与渐变终点必须同时覆盖「基础态」与「group-hover 态」，否则悬停瞬间出现色差；条件类名走 `cn` + 完整字面量，不做动态拼接，Tailwind 才能扫到。
- 层叠校验：构建产物中 `.bg-muted` / `.to-background` 等基础类在前（约 40k / 50k 字节偏移），`.group-hover:*` 变体统一落在后段（约 70k），变体不会被基础类反向覆盖。
- 验证（逐项）：`pnpm exec eslint` 0 告警；编辑器诊断 0 条；`vite build` 后产物含 `.bg-linear-to-r`、`.from-transparent`、`.to-background`、`.to-secondary`、`.group-hover\:to-muted`、`.rounded-xs` 与 `--radius-xs:.125rem`。

## 修正：词条覆盖层底色改用与按钮完全相同的 token

- 问题：覆盖层此前用 `bg-background` / `group-hover:bg-muted`，但词条按钮（`outline` variant）在深色下的实际底色是 `dark:bg-input/30`（悬停 `dark:hover:bg-input/50`），两者不是同一个 token，覆盖层与按钮拼在一起有明显色差。
- 定位依据：`--input = var(--vscode-input-border, var(--vscode-panel-border, #80808059))`，即 35% 透明灰；30% / 50% 再乘一次 alpha，叠在 `--popover` 的 `#252526` 上分别得到 `#2E2E2F` 与 `#343435`，与界面实测值一致。
- 改法：覆盖层只在悬停 / 聚焦时可见，因此不需要「基础 + hover」两套，直接取按钮的悬停态——未选中 `bg-muted dark:bg-input/50`（亮色走 muted，深色走 input/50），选中 `color-mix(in oklch,var(--secondary),var(--foreground) 5%)`；左侧渐变终点同步为同一色（`to-muted dark:to-input/50`）。
- 关键约束：`dark:` 变体编译为 `:is(.dark *)`，特异性比无变体类多一个类选择器，深色值不会被 `bg-muted` / `to-muted` 反向覆盖，不依赖样式表顺序。

## 修复：鼠标移到编辑 / 删除上时预览浮层收起

- 原因：`HoverCardTrigger asChild` 只包了词条按钮，而编辑 / 删除图标是它的兄弟节点（覆盖层 div 的子元素）。鼠标进入图标即触发按钮的 `pointerleave`，`closeDelay` 到点后浮层关闭。
- 改法：把「按钮 + 图标覆盖层」收进一个 `div.relative`（`cell`），`HoverCardTrigger asChild` 绑这个 div，触发区与格子同尺寸；`group` 仍留在最外层，覆盖层里的 `group-hover:*` 与文字淡出逻辑不变。
- 附带影响：预览锚点由按钮变为同尺寸的单元格，`side="top"` 的位置基本不变；键盘焦点从内部按钮冒泡到该 div，聚焦时仍会打开预览。
- 验证（逐项）：`pnpm exec eslint` exit 0；`pnpm exec tsc --noEmit` exit 0；`vite build` 通过（3.04s）。

## 修复：打开图片详情弹窗时自动弹出删除按钮的 tooltip

- 现象：`ImageDetailDialog` 一打开，「删除图片」按钮的提示气泡就浮在按钮上方，未做任何悬停或键盘操作。

- 无条件跳转：`WorkflowRouter` 新增 `requestView(view)`（`WorkflowViewRequest` 事件 + 自增 seq），provider 在 workflow 通道单独广播 `{ kind: 'view', view, seq }`；命令侧先 `selectModule(PRESS_MODULE_DIR)`，再 `requestView('chat')`，最后 focus 面板。
- 前端：`useWorkflowRouting` 对 workflow 通道按 kind 分流，新增常驻 `viewRequest`；`WorkflowRenderProps` 增加该字段；`WorkflowPress` 在**渲染期**按 seq 解析并切分区（放 effect 里会多一轮渲染，并触发 `set-state-in-effect` 告警）。
- 分区白名单：`WorkflowPressSection` 改为由 `WORKFLOW_PRESS_SECTIONS` 派生，并拆到新文件 `layout/pressSections.ts`，避免导航组件同时导出常量破坏 fast refresh。
- 配置清理：`zhai.ai.autoFocusOnContext` 不再参与判断，删除 package.json 配置项、config.ts 字段与 docs 表格行。
- 芯片 tooltip：`AiChatRichInput` 的上下文芯片去掉原生 `title`，文件名 span 包 Tooltip，内容为 `displayPath`（相对工作区），`break-all` 换行、`max-w-72` 限宽；悬浮只包文件名，移除按钮提示互不干扰。
