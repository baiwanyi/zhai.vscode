## 修复：提示词悬停不显示预览图

- 现象：`ImagePromptPicker` 里词条悬停没有预览浮层，底部还会出现「本地暂无预览图」提示，尽管 `prompt/images` 下已有大量图片。
- 根因：`readPromptImageBase` 判空用的是 `imageDirScan.listImageFiles([PROMPT_DIR], PROMPT_IMAGE_DIR)`，该函数只列举目录**顶层**文件；而图库按「分类/分组/名称」镜像嵌套存放，顶层只有目录，于是 `files.length === 0` 恒成立，`baseUrl` 永远为 null。前端 `buildPreviewUrl` 因此对每条词条都返回 null，`previewUrl === null` 分支只渲染按钮、不挂 `HoverCard`。
- 修复：判空改为按图库实际层级下探——`promptImageService` 新增私有 `hasAnyImage(dirUri, depth)`，`images → 分类 → 分组 → 文件` 最多两层，命中任意图片即提前返回；扩展名沿用与 `imageDirScan` 同口径的白名单（`png/jpg/jpeg/webp/gif`），读取失败按没有图处理。`readPromptImageBase` 改用该探测结果决定 `baseUrl` 是否为 null，不再依赖只扫顶层的 `listImageFiles`。
- 语义保持：目录（含嵌套）确实无图时 `baseUrl` 仍为 null，前端继续整体隐藏缩略图并提示目录；顶层的扁平哈希图同样算有图。
- 验证（逐项）：`pnpm exec tsc --noEmit` 通过；改动文件 `eslint` 0 告警。

## 修复：提示词词条区出现横向滚动条

- 根因：词条网格用 `overflow-y-auto`，按规范 overflow-x 会被提升为 auto，任何向右越界的子元素都会带出横向滚动条；而每个词条单元格里的编辑 / 删除按钮组用 `absolute -right-1`（右边缘外凸 4px），最右列的格子右边界正好贴着网格内容盒右边界，这 4px 就是唯一越界量。
- 修复：按钮组定位由 `-right-1` 改为 `right-0`，右边缘对齐格子边界、不再外凸（上沿的 `-top-1.5` 保留，属设计意图）。只修这一个根因，不靠 `overflow-x-hidden` 掩盖——网格内除该按钮组外没有可越界元素：列是 `minmax(0,1fr)` 且格子 `min-w-0`，按钮 `w-full`、文本 `truncate` 都已约束在列宽内。
- 排查手段：需确认是否还有其它越界元素时，在 webview DevTools 对网格容器跑 `clientWidth/scrollWidth` 与后代 `getBoundingClientRect().right` 的差值比对，不靠肉眼或截图推断。
- 验证（逐项）：`pnpm exec eslint src/workflow/imagegen/layout/ImagePromptPicker.tsx` 0 告警；编辑器诊断 0 条。
