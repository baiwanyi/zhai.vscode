## 图片 asWebviewUri 首次启用失败：回退与根因修复

- 现象：切到 `webview-uri` 后所有图片都不显示（含此前已缓存过的图）。
- 排查过程：前端 `useWeiboImage` 只把返回值当 `<img src>`，无 `data:` 前缀假设；CSP 的 `img-src` 首项就是 `webview.cspSource`，`asWebviewUri` 地址本应放行；`mediaCacheRoot` 与 `mediaProxy` 的 `cacheDir` 是同一 `joinPath(cacheRoot, 'weibo-media')`，路径一致。
- 定位：`localResourceRoots` 指向的 `weibo-media` 目录在首次打开面板时**尚不存在**（该目录由第一次下载图片时按需 `mkdir`），未存在的 root 会让签发地址全部被拒。
- 处理：`IMAGE_TRANSPORT` 默认切回 `data-url`（立刻恢复功能）；`openWeiboPanel` 在创建 webview 前 `createDirectory(mediaCacheDir)`（失败只 warn，不能因此打不开面板），资源根改用该已创建目录。
- 结论未闭环：根因是推断而非实测，URI 通道保持默认关闭；下次把常量切回 `webview-uri` 重开面板即可验证修复是否有效。

## 大纲滚动改回项目惯例（单页 isScrollable，章纲页三栏自滚）

- 上一版给三个面板各自挂 h-full overflow-y-auto 仍滚不动：AppContent 默认分支只是普通 div，且卷纲页当时的容器高度靠 h-full 在 flex row 里算，容易塌成 auto；同时 AppContent 传 className="flex" + isScrollable 会让 ScrollArea Root 变 flex 容器，与 Radix Viewport 的 size-full 打架。
- 最终结构（PressOutlinePage）：isChapterModule 用 <AppContent className="flex"> 承载三栏（左树 / 详情 / AI 面板各自滚动）；其余模块（卷纲 / 结构 / 伏笔）用 <AppContent isScrollable> 的 ScrollArea 统一滚动，与设置页、角色页等既有页面同一模式。

## AppContent 的 isScrollable 分支加固（滚动不再依赖 children 包裹）

- 根因判断：内容壳是 lex min-h-full flex-col，子项默认 lex-shrink:1，超长内容会被压回一屏高度，表现为「没有滚动条、内容被裁」；另外调用方的 className 之前落在 ScrollArea Root 上，传 lex 这类布局类会直接破坏滚动容器。
- 改动（src/components/AppPage.tsx）：Root 固定为 h-full min-h-0 w-full flex-1 overflow-hidden（lex-1 在 AppPage 里分高度，h-full 兜住非 flex 父级）；调用方 className 移到内容壳（间距 / 对齐才生效）；内容壳加 [&>*]:shrink-0，内容自然撑高后由 Viewport 滚动，children 不需要再套 h-full / overflow-y-auto。
- 影响面：isScrollable 调用方共 6 处传 className——WeiboScreen（gap-3 p-3）、DashboardTrash（gap-2）、dashboard（gap-3）从此真正生效；WechatPendingSection / WorkflowAiChat / PressOutlinePage 走非 scrollable 分支，不受影响。
- 校验：	sc --noEmit、ESLint、Prettier 通过。
