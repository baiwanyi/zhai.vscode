# 2026-10-22

## 修复：角色卡生成等待超时

### 原因

- 真实图像服务（Grsai gpt-image-2，OpenAI 兼容端点）出图需 1~3 分钟，宿主写死 120s 超时先中断；接口实际返回的是标准 `{ created, data: [{ url }], usage }`，解析本身没问题。
- 前端 130s 与宿主 120s 只差 10s，两边谁先触发不确定；前端超时后宿主请求仍在跑，会占住并发锁。

### 变更

- 新增配置 `zhai.image.timeoutSeconds`（默认 300），`PortraitService` 按秒转毫秒传给执行器，下限 30s。
- 前端超时放宽到 15 分钟只做兜底；生成失败时主动调 `pressAi/aiPortrait/abort` 释放宿主锁。
- 执行器区分「超时」「用户取消」「网络层失败」三类文案；识别 undici 的 `UND_ERR_BODY_TIMEOUT` / `UND_ERR_HEADERS_TIMEOUT` / `UND_ERR_CONNECT_TIMEOUT`，统一按超时提示。
- 响应解析兼容 `data[]` 与 `results[]` 两种列表、b64 与 url 两种载荷；`status` 非成功时给出具体状态文案。
- 生成中面板文案改为「出图通常需要 1~3 分钟，请保持弹窗打开」；宿主记录开始/完成/失败耗时日志，便于核对服务商速度。

### 依据

- 用户实测报「等待超时」，并给出真实响应体（`data[0].url`）。
