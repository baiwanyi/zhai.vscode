## 修复：角色卡生成等待超时

### 原因

- 真实图像服务（Grsai gpt-image-2，OpenAI 兼容端点）出图需 1~3 分钟，宿主写死 120s 超时先中断；接口实际返回的是标准 `{ created, data: [{ url }], usage }`，解析本身没问题。
- 前端 130s 与宿主 120s 只差 10s，两边谁先触发不确定；前端超时后宿主请求仍在跑，会占住并发锁。

### 变更

- 新增配置 `zhai.image.timeoutSeconds`（默认 300），`PortraitService` 按秒转毫秒传给执行器，下限 30s。
- 前端超时放宽到 15 分钟只做兜底；生成失败时主动调 `pressAi/aiPortrait/abort` 释放宿主锁。
- 执行器区分「超时」「用户取消」「网络层失败」三类文案；识别 undici 的 `UND_ERR_BODY_TIMEOUT` / `UND_ERR_HEADERS_TIMEOUT` / `UND_ERR_CONNECT_TIMEOUT`，统一按超时提示。
- 响应解析兼容 `data[]` 与 `results[]` 两种列表、b64 与 url 两种载荷；`status` 非成功时给出具体状态文案。
- 生成中面板文案改为「出图通常需要 1~3 分钟，请保持弹窗打开」；宿主记录开始/完成/失败耗时日志，便于核对服务商速度。

### 依据

- 用户实测报「等待超时」，并给出真实响应体（`data[0].url`）。

## 修复：图像服务 400「excessive system load」提示不友好

### 原因

- 服务商侧负载过高时返回 400 + `{"error":{"message":"excessive system load"}}`，此前把原始 JSON 直接拼进错误文案，用户看不懂也不知道能否重试。

### 变更

- 非 2xx 响应改走 `describeImageFailure(status, body)`，不再直接暴露响应原文。
- 新增 `readFailureMessage`：兼容 `{error:{message}}`、`{error:'...'}`、`{message}`、`{detail}` 与纯文本，超长截断 160 字；配套 `parseJsonQuietly` 宽松解析。
- 过载/限流关键字（excessive system load、overloaded、too many requests、rate limit 等）与 429/503 统一提示「图像服务当前繁忙（服务商负载过高），请稍后重试」。
- 401/403 指向 `zhai.image.apiKey`，404 指向 `zhai.image.baseUrl` 与 `zhai.image.model`，5xx 提示内部错误；所有文案以「图像服务」开头，与上层原样透传逻辑一致。

### 依据

- 用户报错原文：`图像服务返回 400：{"error":{"message":"excessive system load"}}`。

### 验证

- `pnpm exec eslint src/modules/press/ai/aiPortraitGenerator.ts`：通过。
- `pnpm run typecheck`：通过（exit 0）。

### 涉及文件

- `src/modules/press/ai/aiPortraitGenerator.ts`
