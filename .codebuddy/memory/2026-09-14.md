- 关键阻碍与解法：TypeScript 7.0 不提供程序化 API，typescript-eslint 检测到 TS major ≥ 7 会直接抛错。按官方 TS 7.0 发布说明用 npm 别名并行：`typescript: npm:@typescript/typescript6@^6.0.2`（提供 tsc6 与 TS 6 API），另加别名 `@typescript/native: npm:typescript@^7.0.2` 保留 TS 7 的 tsc。实测 tsc=7.0.2、tsc6=6.0.3，typecheck 正常。

- 规则要点：全局 `linterOptions.noInlineConfig`（落地「禁止 eslint-disable 注释」约定）；import-x/order 按 builtin → external → internal → sibling/index → type、组内字母升序、组间无空行；no-explicit-any / consistent-type-imports / explicit-function-return-type 为 error；react/prop-types 关闭（由类型系统承担）；react-hooks 只启用经典两条（v7 其余 15 条属 React Compiler 语义）。

## 构建与类型检查的 TS 版本分工（核查结论）
- `pnpm run typecheck`（`tsc --noEmit`）跑的是 TS 7.0.2：`node_modules/.bin/tsc` 的 shim 指向 `typescript@7.0.2`（由别名包 `@typescript/native` 提供），实测 `--version` 输出 7.0.2。
- `pnpm run compile` 不调用 tsc：扩展宿主由 esbuild 打包（自带 TS 解析器，仅擦除类型）、webview 由 Vite 8 打包（esbuild/rolldown 转译），两者都不做类型检查，产物构建与 TS 版本无关。
- 编辑器语言服务使用 `typescript` 别名指向的 TS 6 API 包（npm 包版本 6.0.2）；`tsc6` 可手动调用（`tsc6 --version` 输出的 6.0.3 是编译器内部构建号，与 npm 包版本不同）。

## TS 版本分工固化（用户要求）
- `compile` 脚本改为 `pnpm run typecheck && node esbuild.mjs && pnpm run webview:build`：编译前用 TS 7（tsc bin 来自别名包 @typescript/native）做类型检查，类型错误会阻断构建；`package`（vsce）沿用 compile，故同样受检。
- lint 链路继续使用 TS 6 API（typescript-eslint 依赖的 `typescript` 别名指向 @typescript/typescript6），两条链路互不干扰。
- `watch` / `watch:all` 未加入类型检查（开发模式避免反复全量检查）；如需实时类型反馈，应另起 `tsc --noEmit --watch` 进程。
- 版本核对：typescript 7.0.2 与 @typescript/typescript6 6.0.2 均为 npm latest，无需升级。
- `watch:all` 加入第三个并发进程：`tsc --noEmit --watch`（TS 7），三路输出前缀 host / web / ts（blue/green/yellow）；已实测 TS 7 监听模式可正常启动并进入 Watching for file changes。`watch`（仅宿主）保持不含类型检查。
