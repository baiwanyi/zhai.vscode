## 本机 pnpm 12 符号链接失效（重要环境问题）
- 现象：`pnpm add` 后新装的带 peer 依赖的包（shadcn、radix-ui、lucide-react）在 `node_modules/<pkg>` 处链接失效——链接目标指向不含 peer 后缀的目录名（如 `.pnpm/shadcn@4.21.0`），而实际目录名带后缀（`.pnpm/shadcn@4.21.0_supports-color@..._typescript@...`）。既有包（react、vite、esbuild 等）链接正常。
- `pnpm install` 判定 "Already up to date"，不会重建坏链；需手动 `New-Item -ItemType Junction` 指向正确虚拟目录修复。
- 另注：CLI 首次批量 `pnpm add` 曾报 `ERR_PNPM_PACKAGE_MANAGER_REMOVE_MODULES_DIR`（拒绝访问 os error 5），在 node_modules 已存在后重试即成功。
- 本机安全删除策略（Safe-Delete）要求移入回收站，而该功能在本系统不可用，导致目录无法通过命令删除（本次临时目录 `.shadcn-probe` 需手动清理）。

## CLI「检测不到框架」的根因与修复（用户确认后实施）
- 根因：shadcn CLI 的框架检测只用 glob `**/{next,vite,astro,app}.config.*`（cwd 内深度 ≤3）判定 Vite，即**只认 `vite.config.*` 这个文件名**；原配置名 `vite.webview.config.mjs` 不匹配，故 init/apply/info 一律报 could not detect a supported framework（与根目录缺 index.html、react 不在 dependencies 无关）。
- 修复：`vite.webview.config.mjs` 重命名为 `vite.config.mjs`；package.json 三处脚本去掉 `--config`（改为 Vite 默认读取，root 仍为 src/webview，行为不变）；tsconfig.json 的 include 同步；配置头部注释补充「文件名须保持 vite.config.*」约束。
- 结果：`pnpm dlx shadcn@latest info` 已输出 framework Vite、tailwindCss src/webview/index.css、importAlias @；`apply --preset b1s91W1fW --yes` 11.2s 执行成功（重装 button、重写 CSS 变量）。
- preset 完整参数（由 info 解析）：style nova、baseColor neutral、theme cyan、chartColor cyan、font inter、fontHeading inherit、radius default、menuAccent subtle、menuColor default-translucent。
- 风格约束：CLI 写入的组件与 components.json 为官方风格（双引号、2 空格缩进），每次 apply/add 后会覆盖回官方风格，需重新按项目风格改写（button.tsx、lib/utils.ts、components.json 已改回）；`src/webview/index.css` 的格式与头部注释不会被 CLI 重排。

## pnpm 坏链问题会复发（重要）
- apply/add 内部会执行 `pnpm add`，重建顶层符号链接时再次把带 peer 的包写坏（radix-ui、shadcn、lucide-react 的链接 target 漏掉 peer 后缀），表现为 tsc 报 TS2307 Cannot find module 'radix-ui'；`pnpm install` 不会修复。
- 处理：手动 `New-Item -ItemType Junction` 指向 `.pnpm/<pkg>_<peers>/node_modules/<pkg>` 重建。长期方案待用户决策：升级 pnpm（当前 12.3.4）、或 nodeLinker: hoisted（需重建 node_modules，本机删除权限可能受阻）、或固化一个修复脚本。
