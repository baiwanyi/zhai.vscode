## 修复 Dialog 内 Combobox 下拉无法打开

- 根因：`@components/ui/combobox` 的 ComboboxContent 固定用 Base UI Portal 挂到 body，脱离 Radix Dialog 的模态焦点区，popup 获得焦点时被 Dialog 焦点陷阱拉回而立即关闭。
- 曾尝试把 Portal 容器改挂 Dialog 内容节点（ComboboxContent 加 container、Dialog 加 contentRef），但 Dialog 内容带 `translate(-50%,-50%)` 变换会成为 fixed 定位的包含块，导致 Base UI Positioner 计算错乱、弹层集中在右侧上下飘动；该方案已撤销，共享组件与通用 Dialog 恢复原样。
- 最终方案：`SearchableSelect` 用 Base UI `inline` 模式（`open` 恒 true，面板显隐由组件自身状态控制，触发区 onClick 展开）；面板不走 Popup/Portal/Positioner，改用 `position: fixed`，按触发区与 Dialog 内容节点的 getBoundingClientRect 差值算 top/left/width，因此不参与 Dialog 内部滚动区高度计算。通用 Dialog 新增 contentRef 暴露内容节点。外部 pointerdown 收起，选中后关闭。
- 关键坑：inline 模式传受控 `open` 会让列表判定为不可见；`absolute` 面板虽脱离文档流但仍撑大 Dialog 滚动区，用户感觉「占用高度」，必须改 `fixed`。
- 涉及文件：`src/workflow/press/outline/layout/ClueTrackEditDialog.tsx`、`src/components/Dialog.tsx`、本日志。
- 校验：`pnpm run typecheck` 通过、命令行 ESLint 2 文件 0 错误；实际交互需用户在宿主中验证。
