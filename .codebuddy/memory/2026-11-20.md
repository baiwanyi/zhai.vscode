## 微博关注时间线（网页版 ajax）

- 新增关注时间线取数链路：Cookie 鉴权 → 单页请求 → 分页/增量 → 字段归一化 → 面板列表。

## 微博图片 UND_ERR_CONNECT_TIMEOUT：加代理通道与 IPv4 直连

- 现象：`fetch failed / UND_ERR_CONNECT_TIMEOUT`，TCP 连接阶段超时（非 TLS、非 403），说明宿主进程到 sinaimg 连不上。
- 判断：扩展宿主不继承浏览器系统代理；浏览器能看图而宿主超时，通常是代理未覆盖到 Node。
- 改进：取图改为三级——代理（`http.proxy` 或 `HTTPS_PROXY`，CONNECT 隧道 + Basic 认证）→ 直连 `node:https`（`family: 4`，连接超时 6s）→ 内置 fetch。证书校验跟随 `http.proxyStrictSSL`。
- 日志按 `proxy` / `direct` / `fetch` 标记，便于判断走到哪一级。

涉及文件：

- `src/modules/weibo/mediaProxy.ts`：CONNECT 隧道、IPv4 直连、三级降级
- `src/modules/weibo/panel.ts`：读取 `http.proxy` / `http.proxyStrictSSL`

## 微博图片 direct 超时：并发闸门 + 视口懒加载

- 日志判读：`direct 失败（直连超时）` 与 `图片超过体积上限` 同时出现，说明连接本身可达，超时主因是**一页几十张图同时发起**，把本地连接表与图床限流打满。
- 宿主：同时下载数限为 4（排队），直连失败重试一次，单张上限提到 24MB，超限自动改取 `/bmiddle/` 缩略图。
- 前端：配图/头像/表情改用 `IntersectionObserver`（`rootMargin: 240px`）懒加载，`useWeiboImage` 收到空地址时表示「未进入视口」，既不请求也不置失败。
- 结论：图片取数链路的正确姿势是「少量并发 + 可见即取 + 逐级降级」，不是单纯调大超时。

涉及文件：

## 微博图片改回传 data URI（绕开 Webview 本地资源授权）

- 调研结论：Webview 加载本地文件要求 `localResourceRoots` 与 `cspSource` 双放行，缓存目录不在扩展目录下、远程开发（SSH/WSL）等场景会出现 `ERR_ACCESS_DENIED`；这是社区高频问题（Stack Overflow / CSDN 均有同类案例）。
- 方案：`weibo/image` 改为读缓存文件生成 `data:` URI 回传（CSP 已允许 `data:`），不再依赖 `asWebviewUri`；`localResourceRoots` 只保留扩展产物目录。
- 单张 >4MB 不内联；前端 `<img>` 增加 `onError`，解码失败显示破图占位，便于区分「下载失败」与「渲染失败」。
