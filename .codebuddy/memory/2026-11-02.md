## 决策：wechat.db 不迁到 {存储根}/sqlite/，后续统一做快照备份

- 现状：`index.db` / `ai.db` / `naming.db` / `press.db` / `wechat.db` 都在 cacheRoot（`<globalStorage>/../zhai.vscode`），只有可重建的 `media.db` 在 `{存储根}/sqlite/`。
- 结论：`wechat.db` **保持不动**，不迁移到存储根；本次只记录决策，不改代码。
- 理由：`wechat.db` 是唯一数据源（账号摘要、批次、文章元信息、`msg_data_id`、发布状态），丢了无法重建；`media.db`/`index.db` 是可从磁盘重建的索引缓存，`media.db` 还有 `.corrupt-<时间戳>` 自愈。存储根普遍在云同步目录，SQLite 的 `-wal`/`-shm` 分开同步容易产生写一半的库；账号属于全局配置，跟某个存储根绑定后换目录即看不到账号。
- 后续计划（尚未实现）：所有仍放在 globalStorage 的库（index / ai / naming / press / wechat）定期快照备份到存储根，建议用 `VACUUM INTO` 生成事务一致的整库快照（避免拷贝到半个库），落在 `{存储根}/sqlite/backup/`，备份只写不读，线上库仍是唯一读写入口。
- 涉及文件：无（仅记录决策）
