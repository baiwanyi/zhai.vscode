## 仪表盘 → 工作流页按模块类型动态匹配（写作管理复用现有页，公众号管理与笔记编辑占位）

### 决策落地
- 写作管理（`press` 模块）→ 复用现有 AI 对话工作流页；公众号管理（`wechat` 模块）→ 占位页。
- 笔记编辑场景（聚焦在 `notes/` 下已索引文档）→ 占位页；无场景（无编辑器、索引外文件、其他模块）→ 对话页。
- 模型维度本轮不参与路由：笔记编辑已固定占位页，故未引入模型类型表、未接 `zhai.ai.model` 配置变更监听；后续启用只需补模型表与 `MODEL_WORKFLOW`，调度代码无需改动。

### 路由机制
- 契约 `src/shared/types/workflow.ts`：`WorkflowId`（`chat` / `placeholder`）、`WorkflowSceneKind`（`module` / `editorNote` / `idle`）、`WorkflowContextState`、`workflow/open` 出入参；收窄函数 `isWorkflowContextState` 与 `isOpenWorkflowRequest`（模块键限 `^[a-z][a-z0-9-]*$`，从源头排除路径形态字符串）。
- 前端 `src/webview/workflow/`：`routing.ts`（`MODULE_WORKFLOW` / `SCENE_WORKFLOW` / `resolveWorkflow` / `contextFingerprint`，无组件依赖可直接单测）、`registry.ts`（WorkflowId → 组件）、`WorkflowHost.tsx`（唯一切换点，未就绪渲染骨架）、`hooks/useWorkflowRouting.ts`（拉快照 + 订阅 workflow 通道 + 覆盖按场景指纹自动失效）、`layout/WorkflowPlaceholder.tsx`（占位页，含「仍然使用 AI 对话」出口）。
- 宿主 `src/modules/ai/workflowRouter.ts`：汇聚活跃编辑器场景与入口意图；场景判定复用 `IndexService.toRelativePath` + 索引库回查（与仪表盘活跃笔记同口径）；编辑器焦点变化 800ms 去抖；入口意图一次性、读取即消费，无面板订阅时不消费。
- 协议新增：`workflow/state`（request，读即消费）、`state{channel:'workflow'}`（广播）、`workflow/open`（仪表盘 → 宿主）；白名单新增 `zhai.openAiChat`；`zhai.openAiChat` 命令支持携带 `{ module }` 意图。
- 解析优先级：用户覆盖 → 入口显式模块 → 模块场景映射 → 笔记编辑场景 → 模块兜底 → `chat` 默认。

## 插件更名、视图 id 重命名、测试目录收敛与缓存目录固定

### 决策落地
- 视图 id `zhai.aiChat` → `zhai.workflow`（package.json 视图声明 + `AiChatViewProvider.viewId` + 两处 `zhai.workflow.focus`）；命令名 `zhai.openAiChat` 保持不变。

- 测试资产统一到 `src/__test__`（10 个 `*.test.ts` + `stubs/vscode.ts`），`src/tests` 目录删除；vitest 的 include 改为 `src/__test__/**/*.test.ts`，`vscode` 桩 alias 指向新位置。测试文件内相对导入按新位置全部改写。
- 索引与 AI 缓存目录固定为全局存储下的 `zhai.vscode`：新增 `resolveCacheRoot(globalStorageUri)`，取全局存储目录的兄弟目录，与文档存储根 `.zhai` 分离；不改扩展标识，避免 globalState（置顶列表、initialized 标记）迁移丢失。

### 关键约束与坑
- `resolveCacheRoot` 接收 `vscode.Uri` 而非 ExtensionContext，便于单测并与 `openSqliteDatabase` 入参风格一致。
- 批量改写会改变文件物理行尾（工具写入为 LF，工作区既有文件为 CRLF），已按工作区现状统一为 CRLF；`core.autocrlf=true` 下 git 提交内容不受影响。
- 既有文件的 Prettier 告警仍源于 CRLF 与 `.prettierrc.json` 的 `endOfLine: lf` 冲突，属仓库既有状态。
