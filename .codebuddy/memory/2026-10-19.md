## AI 对话底部输入区改造：命令 / 参考 / 模式切换 / Token 圆环 / 增强 / 写回编辑栏

### 变更

- 输入区改为三段式卡片（`InputGroup` + `block-start` / `block-end` 两个 addon）：顶部工具行仅「命令」「参考」两个按钮，中间多行输入框，底部左侧模式按钮 + 右侧三按钮。
- 命令菜单四项：改写 / 润色 / 找错别字 / 去 AI 味，点击把指令模板填入输入框（已有内容时追加一行）；命令带 `applyPolicy`，找错别字为 `report` 不提供写回。
- 参考菜单四项（古诗词 / 名言名句 / 经典文本 / 历史资料）为占位，点击仅提示「即将上线」，不发起请求；清单由 `AI_REFERENCE_SOURCES` 驱动，置 `enabled` 即可接入。
- 底部新增模式切换（对话 / 写作），经 `ai/setMode` 写入 `conversations.mode` 持久化，生成中禁用。
- 右下三个按钮：Token 圆环（SVG 自绘，<70% 主色 / 70~90% 警示 / ≥90% destructive，Popover 显示已用 / 预算 / 剩余）、增强提示词（本地规则化补齐任务与要求，二次点击还原）、发送 / 停止。
- 增强提示词的规则化纯函数放入既有 `aichat/utils.ts`，不新增工具文件；`readAiStateKind` 增加 `writeTarget`。
- 移除输入区齿轮按钮，设置入口迁移到 `zhai.workflow` 视图标题栏（`menus.view/title` + `zhai.openSettings` 的 `$(gear)` 图标）。
- 写作模式写回：`ai/writeState` 下发实时目标、每条可写回消息的作用域与已写回集合；`ai/applyWrite` 只接受消息 id，宿主用发送时快照的 uri / `document.version` / range 校验后 `WorkspaceEdit.replace` 写入，进入撤销栈；整篇覆盖前界面二次确认。

- 写回快照按助手消息 id 隔离（不同轮次互不覆盖），可写回与已写回集合按会话隔离，删除会话时一并清理。

- 生成结束后前端刷新运行时用量与写回状态，宿主在模式切换、生成完成、写回成功、删除当前会话时广播 `kind: writeTarget`。
- `AiChatStatusHint` 增加模式提示层级，并修正原「Ctrl+Shift+L 聚焦123」文案。

## 输入区芯片回归内联流（芯片与正文同行、换行回左边缘）

### 变更

- `AiChatRichInput` 由「flex 容器 + 芯片 + 文本 span」改为**单个 contenteditable 内联流**：芯片为 `inline-flex align-middle` 的 `contentEditable=false` 节点，正文是普通文本节点，因此文本紧贴芯片、换行回到行首（对齐 CodeBuddy）。
- 文本读写改为遍历子节点并跳过芯片；外部改值重写非芯片节点、芯片保留。
- 新增芯片前置 effect：React 新增芯片可能追加到文本之后，统一插到首个文本节点之前，保持「芯片在前、正文在后」。
- Backspace / Delete 命中相邻芯片时改走状态删除（`onClearCommand` / `onRemoveContext`），避免 DOM 与状态不同步。
- 粘贴去掉首部换行，避免内容另起空行；全空白内容归一为空串。

### 依据

- 用户反馈：芯片应跟随文本（同处首行、换行回左边缘），而不是独占一行后再另起文本块。flex 布局无法让后续行回到左边缘，故回归内联流。

## 芯片行内垂直对齐 + 输入草稿跨视图重建恢复

### 变更

- 芯片对齐由 `align-middle` 改为 `align-top`：芯片与正文行同为 20px 行高时与行框完全重合，多行时首行居中不再偏移（`align-middle` 依赖 x-height，会有像素级偏差）。
- 草稿持久化改由宿主内存承担（不用 `vscode.setState`，视图移动会重建实例导致状态丢失）：
  - `AiSessionSnapshot` 新增 `draft: { input, commandId }`；`chatService` 以会话 id 为键保存内存草稿，发送成功 / 删除会话时清除。
  - 新增协议 `ai/draft`（入参正文 + 命令 id，超长截断），前端在输入变化后 300ms 防抖写入。
  - `loadSession` / `switchSession` 返回快照，页面在异步回调中恢复命令（避免在 effect 同步体里 setState）；输入正文由 hook 内部 `restoreDraft` 在本地为空时套用。
  - 命令恢复用 `restoredDraftRef`（每会话一次）与 `commandIdRef`（本地已选则保留）防覆盖。

### 依据

- 用户反馈：多行时芯片与首行文字未居中；切换辅助侧边栏后输入内容丢失。
- 选择宿主内存而非 webview state：WebviewView 移动到其它容器会重建实例，`getState` 不再可靠；宿主内存与视图生命周期无关。

## 写作流程界面：作品设定 / 人物设定 / 大纲工作台 / 生成大纲向导

### 变更

- 新增 `workflow/press` 模块，按写作流程五步落地三个页面：`PressSettingPage`（作品设定）、`PressCharacterPage`（人物设定）、`PressOutlinePage`（大纲工作台），并在 `WorkflowPress` 按 `activeSection` 接入；`setting` / `character` / `outline` 三个既有占位入口从此有实际内容，`naming` 与其余分区行为不变。
- 工作台结构：左卷-章树（状态筛选、卷折叠、卷内加章）、中章纲详情（章名 / 梗概 / 节拍 / 出场人物 / 地点 / 钩子 / 张力 / 目标字数 / 正文进度 / 本卷目标与前情）、右 AI 副驾（真实引用清单 + 三个动作）。宽容器三栏、`@2xl` 两栏、窄容器「树 → 详情」下钻，AI 栏在 `@4xl` 以上出现。
- 响应式全部走 Tailwind 4 容器查询（页面根 `@container`），不使用媒体查询：VSCode 侧栏宽度与窗口宽度无关，媒体查询在 Sidebar 与 Panel 之间切换时判断失真。
- 状态模型新增 `stale`（大纲已变更需复核），四种状态走 `PLAN_STATUS_META` 的文案与 badge 语义变体，状态点用语义色令牌，不写死色值。
- 生成向导三步（输入确认 → 卷纲预览 → 章纲勾选并写入），草案由 `buildOutlineDraft` 按结构模板与节奏偏好本地推导，不伪造 AI 输出；章节写入前按剩余条目重新编号；向导以 key 绑定打开状态重建，避免上次草案残留。
- 设定页分组卡受控折叠、完整度百分比、「补齐缺失项」只展开第一个缺项分组；人物页窄容器初始停在列表，选中后下钻，人物卡分四个 Tab；大纲详情对 `stale` 章节给破坏性提示但不阻断编辑。
- 页内数据由 `WorkflowPress` 单点持有（`SAMPLE_WORKSPACE`），设定 / 人物 / 大纲共读同一份草稿，切分区不丢编辑；`sample.ts` 明确标注为宿主协议接通前的界面数据源。
- 可访问性：图标按钮全部带 `aria-label`，树节点用 `aria-current`，步骤条用 `aria-current="step"`，标签控件与 label 建立 id 关联，人物列表项补 `role` / `tabIndex` / 键盘处理，状态不只靠颜色表达。

### 依据

- 用户给定流程为「新建作品 → 作品设定 → 人物设定 → AI 生成大纲 → 按大纲写作」，故设定与人物从后续能力提为 P0 前置；大纲的主存位置从章节 Frontmatter 改为 `大纲.md`（计划），章节摘要保留为事实，支撑后续偏离检测。
- 侧栏宽度通常 300–500px，三栏并排不可用，必须下钻；概览式三栏仅作为宽容器（Panel 或拖宽侧栏）的增强形态。
- 生成结果暂用本地结构模板而非伪造 AI 文本：界面可完整走通「参数 → 卷纲 → 章纲 → 写入」，且不误导用户认为已接入模型。
