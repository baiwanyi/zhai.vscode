## 变更：AI 使用量页支持手动刷新与定时同步

- 协议：`ai/usage` 新增可选 `force`，仅接受布尔 true 时跳过节流立即重扫 CLI 会话记录；其余形态按普通查询处理，避免误触发全量扫描。
- 宿主：`AiUsageService.syncCreditsFromCli(force)`，force 走 `refresh()`，否则走 5 秒节流的 `ensureFresh()`。
- 前端：`useAiUsage` 增加 `refresh()` 与 30 秒静默轮询（`POLL_INTERVAL_MS`），仅在 `document.visibilityState === 'visible'` 时发请求；加载态改为「请求版本 ≠ 已完成版本」派生，避免在 effect 内同步 setState。
- 页头：新增刷新按钮（`RefreshCw`，请求中禁用并转圈），未同步仍显示破折号。
- 文档：`docs/modules/ai-chat.md` 的协议表与用量页说明补充 force、刷新按钮与 30 秒轮询。
- 测试：新增「force 跳过节流，能立即读到新写入的 CLI 记录」。

## 诊断：用量明细比后台少的原因（只读排查，未改代码）

- 结论一（占 89.7%）：记账功能 `4f161b1` 于 2026-10-23 23:39 才引入，此前的 340 个 CLI 会话、717.53 积分从未写入 `ai_usage_logs`；本地无行则无法反推归属，属不可补的历史缺口。
- 结论二（当前仍在漏）：`CodeBuddyImageProvider.generate()` 经 Agent SDK 驱动 ImageGen 出图，但未接 `UsageRecorder`，每次出图约 5.78 积分全部不入库。上线后 36 个会话中，14 次出图共 80.99 积分无对应行，占该区间积分 98.8%。
- 结论三（小项）：`isAvailable()` 出图前探测（prompt `ok`、`maxTurns: 1`）也产生 CLI 会话，积分通常为 0；3 条 semantic 行因 CLI credit 晚落盘暂为空，刷新后自愈。
- 关键判据：373 个会话中 99.7% 仅含 1 个 requestId，排除「一次请求被 agent 拆成多步导致误判」。
- 复核口径：CLI 总计 374 会话 / 798.98 积分，本地库 20 行 / 0.32 积分，匹配 14 个 id。
- 临时文件：`tmp-diag*.cjs` 及 `tmp-diag-report*.txt` 诊断完成后已清理（会触发 ESLint 解析报错）。

## 变更：用量记账补齐出图与请求标识，积分对账改为以 CLI 为准

- 出图记账：`AiUsageModule` 新增 `image`（展示名「AI出图」），`CodeBuddyImageProvider` 在轮询 SDK 消息时收集 `_requestId`、usage 与成本元数据，随产物经 `settle()` 统一回传；`PortraitService` 在出图成功后按 `image` 模块记一行。此前出图（每次约 5.8 积分）完全不落库。
- 请求标识：`AiNameGenerateResult` 与 `AiAppearanceGenerateResult` 增加 `meta`，取名与外貌生成器在流末块取 `chunk.meta` 后交由服务层记账，`request_id` 不再恒为 NULL。
- 积分对账：`listUnresolvedUsage` 改为 `listUsageForCreditSync`（返回含本地 `credits` 的行，不再限定 `credits IS NULL`），`updateUsageCredits` 去掉 `AND credits IS NULL`；服务层按 1e-9 容差比对，仅写有变化的行，已回填但偏小的值会被修正。
- 文档：`docs/modules/ai-chat.md` 的 module 枚举与用量页说明补充 `image` 与「已回填值随刷新修正」。
- 测试：新增「已回填的积分按 CLI 记录修正，工具调用晚落盘时不会停在部分值」（同时覆盖 `image` 模块归一）。
