## 写作管理：作品详情页、章节管理与分批渲染

### 变更

- 页内路由升级为判别联合（home / press / pressProject），新增 `#/press/{作品名}` 详情路由：作品名以 `encodeURIComponent` 承载，非法编码与越界片段回落首页。
- 作品条目改用 `Item variant="outline"` 加描边，点击由「打开 README」改为进入作品详情；打开 README 下沉到详情页页头。
- 新增作品详情页：页头（返回列表 / 作品名 / 打开设定）、元信息行、全宽「添加章节」按钮、卷分组章节目录。
- 章节聚合：`readProjectDetail` 一次前缀扫描同时产出作品摘要与卷分组；按序号前缀排序，无前缀项排在有序项之后；文档无标题时用去序号前缀的文件名兜底；深层目录归入对应卷。
- 新增「添加章节」：落点为序号最大的卷（无卷则 Chapter/ 根），序号取该落点最大序号 +1，冲突递增重试、绝不覆盖；章节骨架按 press.md 1.3；写盘后立即索引并打开。
- 大作品渲染改为分批：`useProgressiveList` 每批 100 条，哨兵进入 ScrollArea 视口自动追加，另保留手动加载兜底。
- 宿主新增 `press/detail`、`press/createChapter`、`press/openChapter`；打开章节须精确命中索引库路径。
- `usePressProjects` 移出 openProject，作品详情动作下沉到 `usePressProjectDetail`；`PressStatus`、错误提示与元信息格式化收敛到 `press/utils.ts`。

### 依据

- 500 章若一次渲染全部条目会卡顿（press.md AC-2），但章节元数据体量仅约 60KB，故数据一次取回、渲染分批，避免协议分页与卷分组边界对齐的复杂度。
- 观察器必须指定 ScrollArea 视口为 root：webview 中 body 不滚动，用默认视口会导致一次性全部触发或永不触发。
- 「添加章节」的序号与落点全部由索引库口径推导，不在前端计算，避免前后端口径分叉；冲突用写入前存在性检查兜底。
- 章节标题兜底放在宿主侧纯函数中，保证列表与详情展示一致且可单测。

## 写作管理：章节的删除与跨卷移动

### 变更

- 协议新增 `press/deleteChapter`（`dirPath` + `path`）与 `press/moveChapter`（`dirPath` + `path` + `targetVolumeDir`），响应携带新路径、展示名与落点卷。
- 新增 `deleteChapter`：单章移入回收站（`useTrash: true`），并按完整路径清理索引记录。
- 新增 `moveChapter`：移动到目标卷末尾，仅替换文件名序号前缀（保留可读名与正文），目标名冲突时递增序号重试；先清旧路径记录再索引新路径。
- `ProjectIndexer` 增加 `removeFile`，`IndexService` 增加按完整相对路径删除单条记录的方法（不做前缀匹配，避免误伤同前缀文档）。
- 章节条目新增「更多操作」菜单：移动到卷（子菜单列出其他卷与「未分卷」）、删除（确认弹窗）。
- 章节移动成功后，章节列表以 `key` 重挂载并把落点卷作为默认展开项，不用 effect 同步 setState。
- 移动目标卷必须已存在、同卷移动直接拒绝；章节级入口不受「未分卷组不提供卷级操作」限制，历史散章可收进正式卷。
- 删除前检查 `workspace.textDocuments` 中同一 Uri 的 `isDirty`，有未保存修改时拒绝并提示先保存。

### 依据

- 移动 = 追加到目标卷末尾，序号按目标卷重排；不做「插入到第 N 章之后」，避免批量重命名与批量重建索引打断 git 历史与外链。
- 空目录不进索引，自动建卷会造出「看不见的卷」，因此目标卷必须已存在。
- 删除磁盘文件后编辑器内容仍是脏的，用户一旦保存就会把文件写回，须在删前拦下。
- 展开状态改用 `initialExpandVolumeDir` + 重挂载，避免 `set-state-in-effect` 告警。

## 写作管理：卷层级、卷折叠与新建卷

### 变更

- 卷成为必备层级：作品骨架创建时即生成 `Chapter/01-卷1/`，章节一律落在卷下，`Chapter/` 根不再作为新建落点。
- 章节落点支持指定卷：`press/createChapter` 新增可选 `volumeDir`，未指定时取序号最大的卷，作品无卷时落到默认卷1；序号改为卷内独立编号。
- 新增 `press/createVolume`：卷序号取现有最大序号 + 1，目录名 `{两位序号}-卷{N}`，建卷同时写入该卷首章并打开。
- 详情页页头「添加章节」改为「新建卷」；每个卷头右侧提供 `+` 在该卷添加章节，未分卷组不提供入口。
- 章节列表改为按卷折叠：`Collapsible` 承载卷头，默认只展开第一个卷，折叠时不挂滚动观察器，展开后重建。
- 分批渲染从「全局扁平切片」改为「每卷独立分批」（每批 100 条），避免折叠状态与全局切片互相错位。
- 在卷内加章前先展开该卷，保证新章节立即可见；展开状态以用户操作集合为准，未操作时按默认集合派生。

### 依据

- 索引库只记录文档，空目录不会出现在详情页，因此「新建卷」必须同时写入首章，否则会产生看不见的卷。
- 卷内独立编号符合写作习惯（每卷从 01 起），也让卷内分批的边界稳定。
- 折叠与全局切片叠加会导致「展开后面的卷却看不到章节」，改为一卷一 hook、按卷切片可消除该错位。
- 展开状态在渲染期按 `userExpanded ?? defaultExpanded` 派生，避免在 effect 中同步 setState。

## 写作管理：卷的重命名与删除

### 变更

- 新增 `renameVolume`：保留原序号前缀替换卷目录可读名（`01-卷1` → `01-风起长安`），无前缀目录不补前缀。
- 新增 `deleteVolume`：整卷目录移入回收站（`useTrash: true`），并按卷前缀清理索引。
- `ProjectIndexer` 最小接口补 `removeFilesUnder`；`IndexService` 实现按相对前缀删除索引记录并广播状态。
- `projectRepository.listVolumeFilePaths` 提供该卷已登记文档，重命名后据此按新路径重建索引。
- 卷头新增更多操作菜单（重命名 / 删除），未分卷组不显示；重命名走输入弹窗，删除走确认弹窗。
- 协议新增 `press/renameVolume`、`press/deleteVolume`，宿主先回查作品存在再转发给 press 服务。
- `usePressProjectDetail` 新增 `renameVolume / deleteVolume / isUpdatingVolume`，成功后重拉详情。

### 依据

- 序号前缀是排序与卷序的唯一依据，重命名必须由宿主保留，前端不自行拼接目录名。
- 递归移动/删除目录时 watcher 不保证逐文件回调，索引须由宿主按前缀主动清理，否则列表残留旧章节。
- 先清旧前缀再按新路径索引，避免旧记录与新路径并存导致聚合口径错乱。
- 删除放回收站而非永久删除，给误操作留恢复路径。
