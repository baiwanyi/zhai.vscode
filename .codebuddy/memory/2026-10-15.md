## 修复索引路径口径不一致（历史绝对路径 + 盘符大小写）

### 问题
- 索引库历史的 `path` 是绝对形态（`Uri.path`，如 `/d:/vault/notes/a.md`），而上层打开笔记时按相对路径口径拼装，导致记录无法定位到存储根下的文件。
- 索引写入侧：存储根 `Uri` 由配置原始大小写构造（`D:\vault` → `path = D:/vault`），而文件 `Uri` 来自 `root.fsPath` 拼接（盘符被小写 → `d:/vault/...`），直接前缀比较会误判为「不在存储根内」，把绝对路径写进索引。

### 变更
- `noteService.ts`：`openNoteByPath` 入参由 `relativePath` 改为 `indexPath`，新增 `toStorageRelativePath` 归一化——以存储根前缀剥离绝对形态，比较前统一小写并忽略前导斜杠；不属于存储根的绝对路径直接拒绝（`不在存储根内`），归一化结果再交 `toSafeSegments` 做片段校验，越根尝试仍被拦截。
- `indexService.ts`：`toRelativePath` 前缀比较改为两侧 `toLowerCase()`，命中后仍按 `rootPath.length` 切片（大小写不改变长度），根外路径保留绝对形态不做错误剥离。
- `noteService.test.ts`：新增「兼容历史绝对路径形态」「拒绝存储根之外的绝对路径」2 项。
- 新增 `indexService.test.ts`（内存库 + 真实 schema）：覆盖「盘符大小写不同仍写相对路径」「根外路径保留绝对路径」2 项。

### 踩坑
- 测试桩的 `Uri.file` 只做反斜杠→正斜杠转换、不补前导斜杠，与真实 VSCode（`D:\vault` → `/d:/vault`）形态不同；用例因此需按「剥离逻辑」而非「前导斜杠形态」构造断言，避免锁死桩的实现细节。

### 验证
- `pnpm exec vitest run src/modules/note/noteService.test.ts src/modules/common/indexer/indexService.test.ts`：2 文件 13 项通过（`noteService` 9 → 11 项，`indexService` 新增 2 项）；本次 4 个文件改动，未触发提交流程。

## 笔记条目间距始终不生效的根因：变体类的特异性压过普通类

### 现象
- 上一轮把 `ItemGroup` 的 `gap-1` 写上去后，用户反馈「间隔依然还是没变」。

### 根因
- `ItemGroup` 基础样式为 `gap-4 has-data-[size=sm]:gap-2.5`，条目带 `data-size="sm"`，故 `has-data-[size=sm]:gap-2.5`（10px）生效。该变体编译为 `.has-data-\[size\=sm\]\:gap-2\.5:has([data-size=sm]){gap:...}`，多出一个 `:has()` 特异性，**高于**普通 `.gap-1`。
- `cn`（clsx + tailwind-merge）不把「带变体的 gap」与「无变体的 gap」视为同类冲突，两个类会并存，最终由 CSS 特异性决定 → 普通 `gap-1` 被吃掉；`Item` 的 `py-2.5` → `py-2` 是同类普通类，twMerge 能正常替换，所以只有内边距微调生效，条目间 10px 一直没变。

### 修法
- `layout/NotesList.tsx`：两处 `ItemGroup` 改用 `gap-1!`（Tailwind v4 的 important 后缀），产物为 `.gap-1\!{gap:var(--spacing)!important}`，`!important` 稳定压过带变体规则。与 `NotesSelectionBar.tsx` 里 `self-center! h-5!` 是同一手法。

### 排查手法（可复用）
- 先用 `node -e`（在项目根、`pnpm exec` 下）调 `cn()` 直接对比合并结果，判断类名有没有被 twMerge 吃掉；再用 PowerShell 读 `dist/webview/assets/*.css`（压缩成单行的产物，常规搜索工具会截断），以 `IndexOf` + `Substring` 定位目标规则的上下文，确认 important 是否真的落到产物里。

### 验证
- 合并结果核对：`py-2.5` 被移除、`py-2` 保留；`gap-1` 与 `has-data-[size=sm]:gap-2.5` 并存（确认根因）。
- 产物核对：`.gap-1\!{gap:var(--spacing)!important}` 已生成。
- `prettier --check` 全绿；`pnpm run webview:build` 成功。视觉结果交由用户自行核对；本次 1 个文件改动（NotesList.tsx），未触发提交流程。
