## 接入「新建空笔记」（一键空笔记）

### 实现链路
- 前端：「添加」按钮 → `useDashboardActions.createNote` → `request('note/create')`，成功后 `reload()` 并把返回 path 设为选中项。
- 宿主：`DashboardViewProvider.invoke` 增加 `note/create` 分支；`invoke` 返回类型改为 `Promise<unknown>`，`handleMessage` 改 async 并 await 后再回包。
- 服务：新增 `src/modules/note/`（`noteFactory.ts` 纯函数 + `noteService.ts` 落盘/索引/打开）。
- 命令：`zhai.note.new` 注册到 `commands.ts` 与 `package.json` contributes，与侧栏按钮共用 `createAndOpenNote`。

### 关键设计
- 路径 `{存储根}/notes/YYYYMM/{uuid}.md`；UUID 的时间戳位以步长 7 打散分布到 32 位，降低同日文件名的可预测性。
- 内容为 Frontmatter（`title` / `created` / `tags` / `source: manual`）+ `# 标题` + 末尾空行；标题写入 Frontmatter，索引可直接提取而无需回退文件名。
- 不覆盖：写入前用 `fs.stat` 判定存在性，同名则重新生成 ID 重试（上限 5 次）。
- 即时可见：`IndexService` 新增 `indexFile(uri)`，跳过文件监听的 500ms 防抖，落盘后先入库再回包。
- 创建后以 `preview: false` 打开编辑器，光标落在标题下方。
- 安全：目标路径由宿主依据存储根拼装，协议不接受任何路径参数，从源头排除目录穿越。

### 踩坑
- 该版本 `vscode.workspace.fs.writeFile` 只有 2 个参数（不存在 `overwrite` 选项），同名冲突检测改为 `fs.stat` + catch 判定。
- 测试桩需补齐 `fs.stat` / `fs.createDirectory` / `fs.writeFile`，并新增 `readFileContent` / `hasDirectory` 断言辅助。
- `indexService.ts`、`stubs/vscode.ts` 的 prettier 告警经 `git stash` 复验在基线版本同样存在，属既有现象，非本次引入。

### 验证
- `eslint` / `tsc --noEmit` / esbuild 打包 / vite build 全绿。
- 测试 44 项通过：新增 `noteFactory` 8 项、`noteService` 4 项；回归 `contextRefs` 20 项、`chatRepository` 7 项、`chatService` 5 项。
