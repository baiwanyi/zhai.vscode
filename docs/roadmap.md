# 开发路线图 (Roadmap)

**版本**：1.0
**日期**：2026-09-03
**状态**：草案
**适用范围**：BaiwanyiONE VSCode 插件（基于 `docs/modules/` 下 9 篇模块设计文档）

---

## 1. 概述

### 1.1 目标

把 9 个模块的功能清单组织成**有依赖关系、有验收节点、可估算工期**的实施顺序，回答三个问题：先做什么、什么时候算做完、做完需要多久。

### 1.2 排期原则

1. **地基优先**：通用模块与 Markdown 管线是所有业务的依赖，必须先稳定
2. **尽早可用**：优先打通「笔记 + AI」最小闭环，让用户尽早用上，而不是铺完所有模块
3. **风险前置**：外部接口权限（微博 / 公众号）验证成本不可控，提前到阶段 0 作为并行任务
4. **可独立交付**：每个阶段结束都应有一个可使用的增量，而不是半成品堆积

### 1.3 假设

- 单人开发 + AI 辅助，日均有效编码 4~6 小时（按 5h 折算，1d = 5h）
- 已有 docs 中的历史经验可复用（数据模型、验收标准已成型）
- 微博 / 公众号接口权限未验证，相关阶段工期为预估值

## 4. 阶段详情

### S0 — 地基（~55h）

**目标**：打通「文件 → 索引 → 检索 → 界面」主链路，确立全插件的技术公约。

**功能清单**（编号对应 `docs/modules/common.md`）

- C1 Markdown 主存储、C2 元数据索引
- C3 增量监听（FileSystemWatcher + 500ms 防抖）
- C4 全量重建与激活自愈、C5 索引队列与事务批处理
- C6 FTS5 全文检索、C7 全局搜索 `Ctrl+K`
- C8 配置中心、C9 `SecretStorage` 密钥
- C10 命令与菜单、C12 Webview `reqId` 消息协议
- C13 日志与诊断

**交付物**

- 可激活的插件骨架（Webview 侧边栏 + 命令 + 状态栏）
- `index.db` 与完整 DDL（`files` / `files_fts` / 触发器 / PRAGMA）
- 索引服务（增量 + 全量 + 自检）、检索服务
- 消息协议类型定义与宿主/Webview 双向封装

**验收**：见 `common.md` 第 8 节 AC-1 ~ AC-10（重建 1000 文件 < 10s、搜索 < 200ms、密钥无明文等）

**并行任务**：微博 / 公众号接口权限调研（~4h，无代码依赖，产出一页结论回填至 `weibo.md` / `sync-wechat.md` 第 9 节）

---

### S1 — Markdown 管线（~35h）

**目标**：建立统一的解析与生成管线，避免后续每个模块各写一套解析。

**功能清单**（`docs/modules/markdown-one.md`）

- M1 Frontmatter 校验与修复、M2 文档格式化（幂等）
- M8 导出单文件（Markdown / HTML 内联样式）
- M3 增强语法（先支持 `[[双向链接]]`、`#标签`，告警块与 Mermaid 留到 S5）

**交付物**：`unified/remark` 管线封装、格式化命令、导出命令、Frontmatter schema

**验收**：`markdown-one.md` AC-1、AC-2、AC-6、AC-9（格式化幂等、写操作可撤销）

---

### S2 — 笔记（~50h）

**目标**：让既有的一堆 `.md` 文件立刻变成一个可用的笔记库。

**功能清单**（`docs/modules/notes.md`）

- N1 目录笔记本树、N2 标签体系
- N7 全文检索与结果高亮
- N3 自动保存与本地修订快照（≥ 30 版）
- N14 回收站与恢复

**交付物**：笔记侧边栏（树 + 列表 + 搜索）、修订快照与恢复、回收站

**验收**：`notes.md` AC-1、AC-2、AC-5、AC-8

**里程碑 M1**：插件可作为「带 AI 检索能力的 Markdown 笔记工具」日常使用

---

### S3 — 知识库（~45h）

**目标**：把语料变成可检索、可溯源的上下文来源，为 AI Chat 提供弹药。

**功能清单**（`docs/modules/knowledge-base.md`）

- K1 结构感知分块、K2 FTS5 BM25 检索
- K5 增量索引、K6 引用溯源与跳转
- K8 索引状态面板、K9 全量重建
- K11 隐私开关（默认本地，不外发）

**交付物**：分块索引、检索面板、溯源跳转、索引状态视图

**验收**：`knowledge-base.md` AC-1、AC-3、AC-5、AC-6、AC-7

**里程碑 M2**：可基于自己的笔记提问并溯源到原文

---

### S4 — AI Chat（~75h）

**目标**：对话先行，写作模式其次，最后接上 `@` 上下文。

**功能清单**（`docs/modules/ai-chat.md`）

- 第一批（对话能力）：A6 对话模式、A7 会话管理、A8 消息历史、A9 SSE 流式、A11 取消、A16 重试与超时
- 第二批（成本与观测）：A14 用量统计、A17 预算护栏、A10 思维链
- 第三批（写作能力）：A1 模式切换、A2 写作指令、A3 diff 逐段接受、A4 内联续写、A5 选中操作
- 第四批（上下文）：A12 `@` 提及（依赖 S3）、A13 上下文参数面板

**交付物**：AI 面板、流式管理（`useReducer`）、diff 审阅与 `WorkspaceEdit` 应用、用量面板

**验收**：`ai-chat.md` AC-1 ~ AC-10（首字 < 500ms、取消 < 100ms、改动可 `Ctrl+Z` 回退）

**里程碑 M3**：AI 可基于笔记内容改稿，且所有改动可控可撤销

---

### S5 — 小说写作 Press（~130h）

**目标**：从「能写」到「能管理一部长篇」。分两批交付，避免战线过长。

**第一批（~55h）：结构与正文**

- W1 作品管理、W2 卷-章两级树（拖拽/分章/合并）
- W3 章节元信息、W4 编辑器与预览
- W19 版本快照与 diff 恢复
- W22 导出（md / docx / EPUB / PDF）

**第二批（~75h）：AI 副驾与设定体系**

- W5 AI 续写、W6 润色改写、W7 对话生成、W8 描写展开、W9 大纲生成
- W14 角色管理与关系图谱、W15 世界观设定
- W16 大纲三视图、W17 伏笔管理、W18 情节线
- W20 写作统计与热力图、W21 番茄钟
- W10 ~ W13（校对、写评、情感分析、起名）按优先级择机实现

**交付物**：作品树、章节编辑器、AI 副驾面板、角色/设定/伏笔/大纲面板、统计与导出

**验收**：`press.md` AC-1 ~ AC-12

**里程碑 M4**：可完整跑通「新建作品 → 分章写作 → AI 辅助 → 完本导出」

---

### S6 — 阅读（~55h）

**目标**：TXT 小说拿来即读，大文件不卡。**本阶段与 S5 无依赖，可并行或提前**。

**功能清单**（`docs/modules/reading.md`）

- R1 目录扫描、R2 流式 MD5 去重、R3 编码检测
- R4 并发锁与进度、R5 书架
- R6 章节解析、R7 虚拟滚动、R8 进度持久化
- R14 书签、R15 全文搜索（按需建索引）、R18 回收站

**交付物**：书架视图、阅读器（虚拟滚动）、章节导航、书签与搜索

**验收**：`reading.md` AC-1 ~ AC-12（100MB 打开 < 3s、进度误差 ≤ 1 行、源文件只读不被修改）

**里程碑 M5**：大部头 TXT 可流畅阅读且断点续读

---

### S7 — 分发（~50h，待接口权限验证）

**前置条件**：S0 并行任务的调研结论为「接口可用」。若不可用，本阶段降级为「生成待发内容 + 手动复制」。

**功能清单**

- 微博（`weibo.md`）：B1 授权、B2 内容转换、B5 预览、B6 发布回执、B11 幂等、B10 重试；B3 长图、B4 图片上传视权限追加
- 公众号（`sync-wechat.md`）：G1 凭证、G2 Token 并发管理、G3 转换、G4 样式内联、G7 永久素材、G9 草稿创建、G11 预览、G13 重试幂等、G14 错误指引

**交付物**：发布面板（转换 → 预览 → 发布 → 历史）、凭证管理、幂等与重试机制

**验收**：两篇文档第 8 节全部 AC，重点是幂等（不重复发布）、Token 并发（10 并发只刷新 1 次）、错误指引（IP 白名单可诊断）

**里程碑 M6**：从写作到分发一键完成

---

### S8 — 打磨与发布（~45h）

**目标**：把「能用」变成「敢用」和「可以给别人用」。

**内容**

1. **性能**（~15h）：大仓库索引分片让出事件循环、虚拟列表优化、COUNT 缓存、索引 hash 抽样校验
2. **测试**（~15h）：索引用例、检索用例、消息协议用例、各模块 Service 层单测；目标后端/宿主逻辑覆盖率 > 70%
3. **可靠性**（~8h）：超时与退避的统一封装复查、失败不丢数据（草稿保留）验证
4. **文档与发布**（~7h）：用户手册、命令速查表、Marketplace 上架材料、CHANGELOG

**验收**：全部模块 AC 回归通过；无 P0/P1 遗留缺陷

**里程碑 M7**：正式发布

## 5. MVP 快速通道

若希望**尽快用起来**（而非等完整交付），可先只做以下子集，约 **~215h ≈ 43 工作日 ≈ 9 周**：

| 顺序 | 内容 | 来源 | 工时 |
|------|------|------|------|
| 1 | 通用核心：索引 + 检索 + 配置 + 密钥 + 协议 | S0 去掉 C13、C15 | ~45h |
| 2 | Markdown 管线最小集：Frontmatter + 格式化 | S1 去掉导出 | ~20h |
| 3 | 笔记核心：目录树 + 标签 + 检索 + 修订 | S2 | ~50h |
| 4 | 知识库最小集：分块 + BM25 + 溯源 | S3 去掉状态面板 | ~35h |
| 5 | AI Chat 对话 + 写作模式 | S4 第一批 + 第三批 | ~65h |

**MVP 结束时你会拥有**：一个能对整库 Markdown 做全文检索、能用 AI 基于自己的笔记改稿、且所有改动可撤销的 VSCode 写作环境。

剩余模块（写作工作台、阅读器、分发）在 MVP 之后按优先级追加，不影响已交付部分。

## 8. 风险与应对

| 风险 | 影响阶段 | 应对 |
|------|----------|------|
| `better-sqlite3` 与 Electron ABI 不匹配 | S0（阻塞全部） | S0 第一天先做驱动可用性验证；准备 wasm 回退 |
| 微博 / 公众号接口权限不足 | S7 | S0 并行调研；不可用则降级为「生成内容 + 手动发布」 |
| 小说写作模块范围过大导致延期 | S5 | 拆两批交付；第一批结束即有独立价值 |
| 索引在大仓库下卡顿 | S0 / S8 | 分片让出事件循环；超阈值提示改为手动索引 |
| AI 费用失控 | S4 起 | 预算护栏（A17）与上下文截断必须在 S4 第一批就实现，不能延后 |
| 需求漂移（边写边加功能） | 全程 | 严格以各模块文档功能清单为准，新增需求先回填文档再排期 |

## 9. 维护说明

- 各阶段开工前，先更新对应模块文档的「状态」列（待实现 → 进行中 → 已完成）
- 阶段验收以各模块文档第 8 节「验收标准」为准，本文件不再重复列举
- 新需求统一先进入模块文档的功能清单并获得优先级，再进入本文件的阶段排期
- 实际工期与预估偏差超过 30% 时，重新评估后续阶段而非压缩验收标准
