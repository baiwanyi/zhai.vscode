# 大纲模块优化与功能增补方案

**版本**：1.0
**日期**：2026-11-26
**依据**：`docs/modules/press.md` 12. 大纲分层导航（已落地）；`src/workflow/press/outline/` 代码现状
**范围**：优化项 O1~O2 + 新增功能 N1~N5

---

## 一、方案目标

当前模块已扎实实现「卷纲 → 章纲 → 场景纲」三级落地、伏笔表、写前查纲与写后回填闭环，属于**写作执行型工具**。本方案的目标是在不推翻现有数据结构与落盘约定的前提下，补齐方法论要求的**全局导航能力**：结构模板、人物与设定的联动、成长线记录，以及章节质量状态与校准机制。

**不做视图层的粗/中/细颗粒度切换**；全书纲沿用设定页的「故事内核」区块，编写顺序仍为故事内核 → 卷纲 → 章纲。

## 二、现状与差距

| 维度 | 现状 | 差距性质 |
|---|---|---|
| 全书纲 | 设定页「故事内核」区块已聚合 `logline/conflict/theme/arc/ending`，且全部进入 AI 生成上下文 | 已满足 |
| 卷/章/场景纲 | 三级类型完整，场景含欲望/阻碍/选择/结果/情绪 | 已满足 |
| 结构纲 | 已有 5 类全书转折标签与自由命名，缺模板预填 | 引导型缺 |
| 人物纲 | 人物卡有欲望/缺陷/弧光/关系，缺恐惧与秘密；大纲内仅有姓名与动机摘要 | 字段缺 + 展示弱 |
| 成长线 | 只有力量体系与升级体系的规则描述，无阶段实例记录 | 能力缺 |
| 设定纲 | 字段齐全；生成梗概已消费完整快照，正文注入仅题材与风格 | 注入缺 |
| 节奏情绪 | 章级有 `pacing` 与 `tension(1-5)`，可编辑并随章纲落盘 | 已满足 |
| 伏笔线索表 | 埋/收章 + 状态 + 触发者 + 预警齐备，但预警只看回收章 | 局部补强 |
| 时间线 | 不作模块，数据留在 `## 主线` 自由段落供参考 | 明确不做 |
| 章节状态 | 已写/待写由 `wordCount > 0` 客观覆盖，缺「待改/废弃」修订态 | 局部缺 |
| 定期校准 | 信息分散在卷纲、章纲、伏笔、进度四处，缺一次性汇总 | 效率优化 |

关键边界依据（`src/workflow/press/document.ts:7-9`）：大纲按「结构纲 / 卷纲 / 章节内容 / 伏笔线索」四个段落解析与回写；故事核、人物纲、设定纲、节奏情绪与时间线段落原样保留，不解析也不回写。任何新增能力都须先处理这一边界。

## 三、优化项：补强现有能力（优先实施）

### O1. 章节修订标记

**做什么**：`OutlineChapter` 新增正交的 `revision: 正常 | 待改 | 废弃`（缺省「正常」），只表达作者的修订意图，**不替换**现有 `wordCount > 0` 的客观判定，也不参与任何自动链路。

**为什么**：现有「已写 / 待写 / 已完成」已由正文字数客观覆盖，真正缺的只有「待改 / 废弃」两个修订态；若用人工状态替换进度口径，会与字数事实形成双真值源，并波及进度统计、写作位置、伏笔自动回收与空章替换四条链路（`src/workflow/press/utils.ts:806-823,1174`、`src/workflow/press/outline/utils/backfill.ts:59-80`）。

**具体落点**（全部在现有章纲页内，不新增页面或导航模块）：

| 位置 | 组件 | 改动 |
|---|---|---|
| 设置入口 | `layout/ChapterEditPanel.tsx` → `block/ChapterEditMetaFields.tsx` | 在元信息区与阶段 / POV / 钩子同组，加「修订标记」下拉；它是工作标记，不进章纲卡六项 |
| 列表徽标 | `layout/ChapterPanels.tsx` | 章节行在「第N章 + 标题 + 字数」之外加「待改 / 废弃」徽标，不点开即可看到返工章节 |
| 写前提示 | `layout/ChapterFocusPanel.tsx` | 显示当前章标记，避免写前不知道本章已标废弃 |
| 筛选 | `layout/OutlineFilterMenus.tsx` | 第二行在卷筛选与标题搜索旁加「标记」下拉，支持批量筛出待改章节 |

**明确不做**：不在卷纲页承载章级标记；不写入章节正文文件（只写 `大纲.md` 章块键值行）；写后回填不读写该字段。

**约束**：不修改 `summary` / `actualSummary` 分离原则（`src/workflow/press/types.ts:7-9`）；不进入 `isEmptyOutlineChapter`、`collectWrittenRefs` 等自动判定；旧文档缺省按「正常」读取。

**验收**：三态可切换且落盘；旧文档打开后默认「正常」；列表徽标、写前提示、筛选三处口径一致；`summarizeWorkspace`、`collectWrittenRefs`、`isEmptyOutlineChapter` 行为零变化。

### O2. 未指定埋设章提示与状态语义修正

**做什么**：

1. 在 `findClueWarnings`（`src/workflow/press/utils.ts:1197-1231`）中增加「未指定埋设章」提示，触发条件限定为 `status === 'planted' && plant === null && payoff !== null`——只有已规划回收、却缺埋设点的伏笔才提示，避免新建空条目立即告警。
2. 修正 `ClueTrackItem`（`src/workflow/press/outline/block/ClueTrackItem.tsx:23,39`）的状态徽标：`status === 'planted' && plant === null` 时显示「未指定」而非「未回收」，区分「计划中」与「已埋待收」。

**为什么**：现有 `planted` 同时承担「计划埋」和「已埋」两种语义，`createClue` 默认 `status: 'planted'`、`plant: null`（`src/workflow/press/utils.ts:439-451`），新建伏笔列表立刻显示「未回收」。真正的缺口是这两处语义混淆，不是缺少更多告警。

**明确不做**：不做「埋设章已过却未埋」判定（模型无「未埋」状态，不可判定）；不做实时密度告警（阈值主观、长线伏笔必误报），密度检查并入 N5 卷末统计。

**约束**：不扩展 `ClueStatus` 三态，不改 `大纲.md` 的伏笔状态键值；展示修正只影响徽标文案，`plant` 已填的条目行为不变。

**验收**：`plant === null` 的伏笔显示「未指定」，已填埋设章的仍显示「未回收」；新提示在列表顶部与编辑弹窗同时出现；与现有四类回收端提示不重复。

## 四、新增功能（按价值排序）

### N1. 结构模板

- **做什么**：在「结构」模块提供 2~3 套结构模板（三幕 / 起承转合 / 最小可用），套用时预填一组结构阶段（名称、转折类型、叙事作用），确认后覆盖或追加，作者再逐项修改；沿用现有 6 类 `ActKind`，不扩展枚举。
- **为什么**：现有 5 类转折标签与自由命名的 `name` 已能表达主流范式（`src/workflow/press/constants.ts:71-88`、`src/workflow/press/types.ts:46-60`），缺的只是从零搭建的脚手架；模板成本低，能降低新作品的结构门槛。
- **明确不做**：不扩展 `ActKind`（自由命名已够用）；不做 AI 生成结构纲（结构是全书导航主干，契约明确模型不回写结构，错误会沿卷纲与章纲放大）。
- **落点**：`src/workflow/press/outline/layout/StructureActPanels.tsx`（模板入口）、结构段落序列化。
- **验收**：套用模板后阶段按模板顺序落盘；覆盖前有确认；现有手动新增与编辑不受影响。

### N2. 成长线（回填驱动）

**做什么**：

1. **回填新增一张卡**：在回填弹窗加入「识别成长节点」，由 AI 读取已写正文，提取主角境界 / 战力 / 金手指等级的变化，列成建议供作者勾选采纳。
2. **新增 AI 通道**：复用 `pressAi/aiAnalyzeClueRefs` 的形态，新增 `pressAi/aiAnalyzeGrowth`，输入已写章节事实与当前成长表，输出 `{ volumeOrder, chapterOrder, track, value, note }[]`。
3. **新增「成长」标签页**：按卷分组展示已累积节点（主角 / 金手指两列，值保持自由文本），支持编辑与删除做兜底修正，不要求手动逐卷填。

**为什么**：现有只有力量体系（`powerSystem`）与升级体系（`goldenFingerUpgrade`）的**规则描述**，没有「第几卷到了哪一级、战力多少」的**阶段实例**（`src/workflow/press/types.ts:309,320`）；升级流、系统流最容易出战力崩坏与境界跳跃，需要一张可回填的成长线做一致性校验。

**数据模型**：`GrowthPoint { id, volumeOrder, chapterOrder | null, track: 'protagonist' | 'goldenFinger', value, note }`；`value` 为自由文本，兼容「筑基成功」「战力 1000」「+100」三种记法；默认卷级节点，章级可选。

**落盘**：`大纲.md` 新增独立段落 `## 成长线`，按「卷 → 节点」切块，与现有四段互不覆盖。

**安全约束**：沿用伏笔识别的三条规则——AI 建议只作候选、不直接落盘；坐标必须在现有卷章内；写入只追加或更新对应节点，不覆盖其他卷记录。属于「半自动」，勾选后才写。

**明确不做**：不做手动为主录入；不做自动计算与成长曲线；不做与正文数值的强制校验；AI 未识别到时不产生记录。

**验收**：回填可识别并勾选写入成长节点；成长页按卷展示且顺序正确；建议坐标越界时跳过；未勾选不影响落盘。

### N3. 人物卡轻量展示与出场分布

**做什么**：

1. **写前查纲**：卡文自查卡的动机行由「姓名：欲望」扩展为「姓名 + 角色徽标 + 欲望摘要」，只读展示，复用现有 `cast` 数据。
2. **卷卡片出场统计**：卷纲卡片内折叠一行「本卷出场：张三（5 章）、李四（3 章）」，按各章 `characterIds` 聚合，帮助发现「主要人物整卷未出场」。

**为什么**：人物卡在人物页已完整（封面 / 角色 / 欲望 / 详情面板），大纲内目前只有姓名与「姓名：欲望」；缺的是大纲视角的出场分布，这是人物页看不到的检查点。

**明确不做**：不做完整人物卡（封面 + 详情）搬入大纲；不做按阶段/卷的「弧光推进轨迹」（章纲无人物变化字段，只能重排静态文本）；不新增章级人物变化字段。

**后续可选**：人物卡补 `fear / secret`，归人物页独立推进，不并入本项。

**约束**：只读聚合，人物卡仍是唯一数据源；出场统计复用 `characterIds`，不改章纲结构。

**验收**：写前查纲显示角色徽标与欲望；卷卡片显示出场人物与章数；主要人物整卷缺席时能直接从统计看出。

### N4. 设定约束注入

- **做什么**：在「添加到 AI 对话」的章纲文本中补入与本章相关的设定约束：本章地点匹配的 `lore` 条目、金手指的代价与限制、核心概念、禁忌；对注入长度设上限并截断，避免上下文膨胀。
- **为什么**：正文注入目前只有题材与风格（`src/workflow/press/utils.ts:636-638`），而生成章纲梗概时已传入完整设定快照（`toSettingSnapshot`）；同一份设定「补梗概看得到、写正文看不到」，会导致金手指无代价、设定冲突等硬伤。
- **筛选口径**：地点按 `chapter.location` 匹配 `lore` 中 `place` 条目；金手指 / 世界观 / 核心概念 / 禁忌为全书级，始终注入；势力暂不做人物级关联（人物卡无 `faction` 字段），按地点所属或全量注入。
- **明确不做**：不单独新增「设定约束」展示卡（作者可在设定页维护）；不新增 AI 对话通道，复用现有 `ai/context/addInline`。
- **约束**：只注入计划上下文，不混入正文事实；单次注入总量设上限，超长按优先级截断。
- **验收**：写正文注入包含本章地点条目与金手指代价；注入长度不超过上限；未填写的设定项整行省略。

### N5. 卷末统计汇总

- **做什么**：按卷生成一份纯统计汇总：本卷章数 / 已写 / 字数、伏笔未收与逾期数量、本卷出场人物及章数、结构阶段在本卷的覆盖情况；各项数据可点击跳到对应页面。
- **为什么**：方法论要求「每写完一卷检查一次」，当前信息分散在卷纲、章纲、伏笔、进度四处，作者需要逐页翻看；汇总不新增判定，只把既有口径聚合到一处。
- **明确不做**：不做人物弧推进判定（章纲无人物变化字段）；不做主线偏移判定（需语义理解，规则做不到）；不引入 AI 生成报告，全部为确定性统计。
- **约束**：复用 `findClueWarnings`、`summarizeWorkspace` 等既有口径，不另算一套统计；只读展示，不阻断操作、不自动改状态。
- **验收**：汇总数值与各页口径一致；伏笔逾期数与预警列表一致；人物出场章数与按 `characterIds` 聚合结果一致。

## 五、实施路线

| 阶段 | 内容 | 主要价值 |
|---|---|---|
| 一期 | O2 埋设章提示与状态语义、N1 结构模板 | 只改派生层与常量层，不新增数据模型，最快落地 |
| 二期 | N3 人物卡展示与出场分布、N5 卷末统计、N4 设定约束注入 | 全部基于现成数据，解决正文一致性与大纲视角的展示缺口 |
| 三期 | N2 成长线、O1 章节修订标记 | 两者都需要新增持久化字段与 `大纲.md` 段落，同期统一处理落盘与旧文档兼容 |

**分层依据**：一期不改数据模型；二期只消费现成数据；三期新增字段。同一期内的项共享同一批改动面，便于一次完成解析、序列化与兼容处理。N3 与 N5 同源（都按 `characterIds` 聚合出场），必须同批；N2 是唯一需要新增 AI 通道的重项，单独与 O1 合并成期。

## 六、必须守住的设计约束

1. **段落独立落盘**：各模块只写自己的段落，互不覆盖；新增功能必须遵循现有分段落解析约定。
2. **计划与事实分离**：`summary` 与 `actualSummary` 永不互相覆盖，状态字段不得绕过这一点。
3. **引用口径**：伏笔与卷末统计对章节的引用一律用卷序 + 章序，禁止使用章 id。
4. **模块元数据同步**：新增模块须同时更新 `OutlineModuleKey`、`OUTLINE_MODULE_META` 与文档解析三处，否则导航与落盘会脱节。
5. **跨页只读优先**：人物与设定的大纲内呈现一律只读聚合，避免双写冲突。
