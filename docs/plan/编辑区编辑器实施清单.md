# 编辑区 Markdown 富文本编辑器实施清单

**版本**：1.0
**日期**：2026-11-12
**依据**：`docs/plan/编辑区 Markdown 富文本编辑器可行性方案.md` v1.5
**范围**：P0（P0-0 ~ P0-6）+ P1（标注总览页与增强）

## 一、前置约定

### 1.1 已定决策（不再讨论）

| 决策 | 结论 |
|---|---|
| 编辑器内核 | TipTap 3（ProseMirror） |
| 载入形态 | `CustomTextEditorProvider`（`zhai.markdownEditor`），不改全局 `editorAssociations` |
| 打开入口 | 插件打开的文档走富文本，资源管理器 / VSCode 新建走原生（方案 6.5） |
| 文档同步 | 直接读写 `TextDocument`，最小 diff + `WorkspaceEdit`（方案 6.2） |
| Notion-like 基座 | 开源自建，不引入官方商业模板（方案 5.5） |
| 标注存储 | `{存储根}/sqlite/annotations.db`，独立库，不进 `index.db`（方案 8.1） |
| 标注不落正文 | 划线 / 批注不写入 Markdown；块 id 不写入 Markdown |
| AI 查询 | 宿主 `editor/query` + `StreamMessage`，不走 Tiptap Cloud |

### 1.2 通用完成定义（DoD）

每个任务完成需同时满足：

1. `pnpm run typecheck` 通过；
2. `pnpm exec eslint <改动目录>` 通过，不使用任何 `eslint-disable`；
3. `pnpm exec prettier --check` 通过；
4. 新增源文件首部有中文 JSDoc 模块注释（职责 / 复用约定 / 关键约束，3–8 行）；
5. 4 空格缩进；import 分组按 `import-x/order`（builtin → external → internal → sibling → index → type，组内字母序，组间无空行）；
6. 相关单测通过；无对应测试的，在清单末尾测试表里登记"暂缺"与原因；
7. IDE 诊断 0 条；界面核对由用户手工完成，**不生成截图**。

```bash

# 基础能力

# Notion-like 交互（方案 5.5）

pnpm add @tiptap/extension-highlight @tiptap/extension-text-style @tiptap/extension-color
pnpm add @tiptap/extension-text-align @tiptap/extension-image @tiptap/extension-file-handler
pnpm add @tiptap/extension-table @tiptap/extension-task-list @tiptap/extension-task-item
pnpm add @tiptap/extension-emoji @tiptap/extension-mention
pnpm add @tiptap/extension-code-block-lowlight lowlight

```

安装时逐项核对：

- 包名必须是 `@tiptap/*`，出现 `@tiptap-pro/*` 立即停止并改用等价自写；
- `package.json` 中每个包的 `license` 应为 MIT；
- 全部 `@tiptap/*` 锁在同一 minor 版本，必要时在 `pnpm-workspace.yaml` 的 `overrides` 里统一（pnpm 12 不读 `package.json` 的 `pnpm` 字段）；
- `lowlight`、`katex` 用动态 `import()`，不进首屏 chunk。

| 天 | 内容 |

**顺序修正（实施中发现）**：1.3（替换插件内打开入口）必须排在「正文接入」之后。若先切入口，用户从仪表盘打开章节会看到占位文本，等于把日常写作路径弄坏。因此 D3 先做双向同步，D4 再切入口。

第一周结束若 AC-3 不达标，先修往返，不要进 P0-2b——块级交互会把往返问题掩盖得更深。
