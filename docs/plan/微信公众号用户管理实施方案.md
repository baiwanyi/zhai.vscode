> 上位设计：`docs/modules/wechat.md`（第 3、6、7、9、13、15 节），缺陷编号沿用 G24（`docs/modules/wechat.md` 功能清单）。
> UnionID 依据：微信开放文档《UnionID 机制说明》<https://developers.weixin.qq.com/doc/subscription/guide/product/unionid.html>（页面最后编辑 2026-03-08）。
> 完成定义（每个任务均适用）：代码 + 单测 + `pnpm exec tsc --noEmit` + ESLint + Prettier + 对应人工验证项。
> 实施状态：M0–M5 代码已落地（2026-11-27），单测与静态检查通过；平台写接口与 UnionID 返回仍待用户按验证清单实测。行号仅作定位参考，实施时以实际代码为准。

## 0. 现状与结论

### 0.1 已落地的能力

| 层 | 现状 | 位置 |
|----|------|------|
| 页面 | 两段式「粉丝 / 标签」只读列表：头像、昵称、关注状态/时间、标签名与人数；空态、骨架、错误重试均有 | `src/workflow/wechat/fans/WechatFansPage.tsx` |
| Hook | 并行请求列表与标签，两者失败互不影响；每次挂载重新拉取，不本地落库 | `src/workflow/wechat/hooks/useWechatFans.ts` |
| 服务 | 取 openid 首页后只取前 100 个补资料；资料失败降级为「只有 openid」；标签只读 | `src/modules/wechat/fanService.ts` |
| 平台适配 | `user/get`、`user/info/batchget`、`tags/get` 三个读接口已封装 | `src/modules/wechat/openapi.ts` |
| 协议 | `wechat/fans/list`、`wechat/fans/tags` 走白名单分发与类型守卫 | `src/modules/wechat/wechatRoutes.ts`、`src/shared/types/wechat.ts` |
| 作用域 | 六分区共用当前账号；未选账号显示引导空态，切账号按 `key={account.id}` 重挂载 | `src/workflow/wechat/WorkflowWechat.tsx`、`hooks/useWechatAccountScope.ts` |

### 0.2 关键缺口

1. **无 UnionID 字段与关联**：`WechatFanSummary` 只有 `openid / nickname / avatar / subscribeStatus / subscribedAt`，平台批量资料已返回的 `unionid` 被丢弃；跨公众号同一用户无法关联。
2. **无落库**：文档第 6 节声明了 `wechat_fan_tags`，但 `src/modules/wechat/db/connection.ts` 的实际 `SCHEMA_STATEMENTS` 只建账号、批次、文章、素材四张表——该表从未创建。没有本地快照就无法做按标签筛选、搜索、详情与同步状态展示。
3. **无写操作**：标签 CRUD、打标/取消、备注、拉黑/解除均未实现；文档第 15.2 节把这一项列为 P2 待办。
4. **无同步语义**：现在每次进页面直接问平台，既不记录同步时间，也无法在平台失败时展示上一次成功快照。
5. **无搜索与详情**：100 条以内只能肉眼扫，看不到地区、语言、关注来源、标签、备注等已有字段。

### 0.3 三条不可 breaking 的约束

- **平台双重上限**：`user/get` 单页最多 1 万个 openid，`user/info/batchget` 一次最多 100 个。两者错位，翻页必须按 100 一批补资料，不能把 1 万条直接丢给资料接口。
- **平台是唯一真相**：本地库只存快照，不做本地→平台的回写补偿；写操作成功后以平台回读为准更新快照，失败保留旧值并提示。
- **窄侧栏形态**：工作流面板约 300–400px，沿用 `AppPage` + `Item` + `SegmentedRail` + `Dialog` 的既有骨架，不做宽表格、不做多列数据网格。

## 1. 目标与范围

### 1.1 目标

把现有只读的 `fans` 分区扩展为**单账号作用域下的完整用户管理页**：可检索、可筛选、可看详情、可管理标签与备注、可拉黑/解除、可主动同步平台用户数据，并为 UnionID 关联留出稳定的数据契约。

### 1.2 功能拆解

| 编号 | 功能 | 说明 | 优先级 | 依赖 |
|------|------|------|--------|------|
| F1 | 用户列表展示 | 昵称（平台为空时回落备注）、关注状态、关注时间、标签数、OpenID 尾号；不展示头像（平台已不返回）；总数与快照时间常驻页头 | P0 | 现有 FansPage 扩展 |
| F2 | 检索与筛选 | 昵称/备注/OpenID 尾号本地搜索；按标签、关注状态筛选；排序按关注时间倒序 | P0 | 本地快照表 |
| F3 | 用户详情 | 弹窗展示完整资料：OpenID/UnionID（脱敏 + 复制）、地区、语言、关注来源、扫码场景、标签、备注、跨账号关注记录 | P0 | unionid 字段 |
| F4 | 标签管理 | 列表、新建、重命名、删除；删除前二次确认并说明影响 | P1 | 新协议 |
| F5 | 打标与解绑 | 单个/批量给粉丝打标签、取消标签；以平台 `tags/members/batchtagging` / `batchuntagging` 为准 | P1 | F4 |
| F6 | 备注与黑名单 | 修改备注（`user/info/updateremark`）；拉黑/解除拉黑（`batchblacklist` / `batchunblacklist`） | P1 | 写协议 + 二次确认 |
| F7 | 同步用户数据 | 主动触发；游标翻页 + 100 一批补资料；记录进度、结果与失败原因；支持断点续跑 | P0 | 同步任务表 |
| F8 | 绑定状态展示 | 只读展示开放平台绑定状态与 UnionID 可用性；未绑定时给出跳转指引，不阻断其他功能 | P1 | 平台返回判定 |
| F9 | 权限与异常 | 账号作用域、写操作禁用态、错误码归一、脱敏与不写日志 | P0 | 横切 |

### 1.3 非目标（明确不做）

| 项 | 原因 |
|----|------|
| 微信用户 ↔ 本地登录账号绑定 | 本项目是 VSCode 本地单用户插件，没有账号体系；F8 的「绑定」只指公众号与开放平台的绑定状态 |
| 在开放平台侧替用户完成绑定/解绑 | `open.weixin.qq.com` 没有可写公开接口，只能只读判定 + 指引跳转 |
| 群发消息给粉丝 | 属 `push` 分区，且受认证与频率限制，不并入用户管理 |
| 粉丝画像与行为分析 | 平台接口不提供；统计留给 `stats` 分区 |
| 自动定时同步 | 插件不保证常驻；改为进页面时提示「快照已过期」，由用户点同步 |
| 跨账号合并为同一用户 | UnionID 只用于**关联展示**，不合并 openid、不合并标签与备注（各公众号关注关系彼此独立） |

## 2. UnionID 机制与本项目的关联方式

### 2.1 官方机制要点（作为设计依据）

- 公式：`微信用户 + 公众号 AppID = openid`，`微信用户 + 开放平台账号 = unionid`。
- 同一用户在不同公众号下 `openid` 不同；只要这些公众号绑定到**同一个微信开放平台账号**，`unionid` 相同。
- 公众号 AppID 不变则 `openid` 不变；绑定的开放平台账号不变则 `unionid` 不变。
- `user/get` 只返回 openid 列表，不含 unionid；unionid 来自 `user/info` / `user/info/batchget` 的返回字段，**前提是账号已绑定开放平台**。
- 官方页面注明：2021-12-27 之后部分场景不再输出头像、昵称——因此头像昵称必须可缺省，不能作为主键或必填。
- 网页授权 `snsapi_userinfo`、小程序 `code2Session` 的字段级规则不在该页面内，本项目当前也不涉及，不据此做设计假设。

### 2.2 本项目的关联策略

1. **主键仍用 `(account_id, openid)`**：`openid` 在单公众号内稳定且唯一，是平台所有写接口（标签、备注、黑名单）的入参，不能用 unionid 替代。
2. **unionid 作为跨账号关联键**：在 `wechat_fans` 上加 `unionid` 列与 `(account_id, unionid)` 索引；详情页用「该 unionid 在本项目其他公众号下的关注记录」做只读关联展示。
3. **unionid 为空是正常态**：未绑定开放平台、或资料接口未返回时为空。列表显示「—」，详情页显示引导文案「该用户没有 UnionID：公众号需绑定微信开放平台账号」，**不报错、不阻断打标/备注**。
4. **不做身份合并**：同一 unionid 在不同账号下仍保持各自的 openid、关注状态、标签、备注；关联展示只做提示，不写回、不批量操作。
5. **脱敏规则**：列表只露 openid 尾号 6 位；unionid 默认只露尾号 6 位；完整值仅在详情弹窗内「复制」按钮写入剪贴板，界面不常驻明文，日志与诊断不记录。

### 2.3 字段映射表

| 平台字段 / 来源 | 本地字段 | 类型与处理 | 失败/缺省 |
|----------------|----------|-----------|-----------|
| `user/get` → `data.openid[]` | `wechat_fans.openid` | 与 `account_id` 组成主键 | 空列表保留总数，快照标记为空 |
| `user/get` → `total` | `wechat_fans_snapshot.total` | 平台关注者总数 | 回落到 openid 数 |
| `user/get` → `next_openid` | `wechat_sync_tasks.cursor` | 同步游标，空串表示末页 | 中断后按此续跑 |
| `user/info/batchget` → `unionid` | `wechat_fans.unionid` | 可选字符串，仅绑定开放平台时出现 | 写 `NULL`，界面显示「—」 |
| → `nickname` | `wechat_fans.nickname` | 平台自 2021-12-27 起返回空值；空串优先回落为平台 `remark`（公众号后台备注），再回落 openid 前 8 位 | 不把昵称当唯一标识 |
| → `headimgurl` | `wechat_fans.avatar` | 平台自 2021-12-27 起返回空值；字段原样保留但不展示 | 界面不展示头像 |
| → `subscribe` | `wechat_fans.subscribe_status` | `0` 取关 / `1` 已关注 | 缺省按 `0` |
| → `subscribe_time` (秒) | `wechat_fans.subscribed_at` | `new Date(n * 1000).toISOString()` | `0` 写 `NULL` |
| → `remark` | `wechat_fans.remark` | 平台备注，与本地备注合并时以平台为准 | 缺省 |
| → `country/province/city` | `wechat_fans.country/province/city` | 原样存，界面拼「省 · 市」 | 缺省显示「—」 |
| → `language` | `wechat_fans.language` | 原样存 | 缺省 |
| → `subscribe_scene` | `wechat_fans.subscribe_scene` | 原样存，界面映射文案（如 `ADD_SCENE_SEARCH`） | 缺省 |
| → `qr_scene` / `qr_scene_str` | `wechat_fans.qr_scene` | 数字优先，字符串回落 | 缺省 |
| → `tagids` | `wechat_fans.tag_ids` | JSON 数组字符串，与 `tags/get` 交叉校验后入库 | `[]` |
| `tags/get` → `tags[]` | `wechat_tags` | `(account_id, tag_id)` 主键，存名称与平台 count | 单标签失败不影响全表 |
| `tags/members/get` → openid[] | 标签筛选结果 | 与本地快照按 openid 求交集，不另存成员表 | 游标同 `user/get` |

> 注意：`user/info/batchget` 返回的 `tagids` 与 `tags/get` 的人数口径可能短暂不一致（平台统计有延迟），界面以 `tags/get` 的 count 显示人数、以 `tagids` 显示单用户标签，不做强一致校验。

## 3. 数据结构与接口设计

### 3.1 新增/变更表

在 `src/modules/wechat/db/connection.ts` 的 `SCHEMA_STATEMENTS` 追加（顺序在账号表之后）：

```sql
-- 用户快照：平台是唯一真相，本表只存最近一次同步结果
CREATE TABLE IF NOT EXISTS wechat_fans (
    account_id        TEXT NOT NULL,
    openid            TEXT NOT NULL,
    unionid           TEXT,
    nickname          TEXT NOT NULL DEFAULT '',
    avatar            TEXT,
    subscribe_status  INTEGER NOT NULL DEFAULT 0,
    subscribed_at     TEXT,
    remark            TEXT,
    country           TEXT,
    province          TEXT,
    city              TEXT,
    language          TEXT,
    subscribe_scene   TEXT,
    qr_scene          TEXT,
    tag_ids           TEXT NOT NULL DEFAULT '[]',
    last_synced_at    TEXT NOT NULL,
    created_at        TEXT NOT NULL,
    updated_at        TEXT NOT NULL,
    PRIMARY KEY (account_id, openid)
);
CREATE INDEX IF NOT EXISTS idx_fan_unionid ON wechat_fans(account_id, unionid) WHERE unionid IS NOT NULL;
CREATE INDEX IF NOT EXISTS idx_fan_subscribed ON wechat_fans(account_id, subscribe_status, subscribed_at DESC);

-- 标签：文档第 6 节已声明但从未建表，本方案补齐
CREATE TABLE IF NOT EXISTS wechat_tags (
    account_id  TEXT NOT NULL,
    tag_id      INTEGER NOT NULL,
    name        TEXT NOT NULL,
    count       INTEGER NOT NULL DEFAULT 0,
    updated_at  TEXT NOT NULL,
    PRIMARY KEY (account_id, tag_id)
);

-- 同步任务：一次同步一行，游标支持断点续跑
CREATE TABLE IF NOT EXISTS wechat_sync_tasks (
    id            TEXT PRIMARY KEY,
    account_id    TEXT NOT NULL,
    status        TEXT NOT NULL,        -- running|success|partial|failed
    cursor        TEXT NOT NULL DEFAULT '',
    page_count    INTEGER NOT NULL DEFAULT 0,
    fetched       INTEGER NOT NULL DEFAULT 0,
    created_count INTEGER NOT NULL DEFAULT 0,
    updated_count INTEGER NOT NULL DEFAULT 0,
    unfollowed    INTEGER NOT NULL DEFAULT 0,
    failed_count  INTEGER NOT NULL DEFAULT 0,
    total         INTEGER NOT NULL DEFAULT 0,
    error_code    INTEGER,
    error_hint    TEXT,
    started_at    TEXT NOT NULL,
    finished_at   TEXT
);
CREATE INDEX IF NOT EXISTS idx_sync_account ON wechat_sync_tasks(account_id, started_at DESC);
```

**约束**

- 不新增密钥列；`AppSecret` 仍只在 `SecretStorage`。
- 旧库升级用 `CREATE TABLE IF NOT EXISTS`，不做数据迁移；本方案不改动现有四张表结构。
- `tag_ids` 存 JSON 字符串，写入前按数字升序去重，避免平台返回顺序抖动造成无谓更新。
- 删除账号时一并删除这三张表中该账号的行（沿用现有账号删除流程补清理）。

### 3.2 协议方法（只增不改）

| 方法 | 请求 | 响应 | 说明 |
|------|------|------|------|
| `wechat/fans/list` | 现有 | 现有 + `syncedAt?: string` | 兼容扩展：优先读快照，快照为空时回落实时接口 |
| `wechat/fans/tags` | 现有 | 现有 | 改为读 `wechat_tags`，失败回落平台 |
| `wechat/fans/search` | `{ accountId, keyword?, tagId?, subscribeStatus?, limit?, offset? }` | `{ fans, total, matchedTotal }` | 本地快照查询；关键词只匹配 nickname/remark/openid 尾号 |
| `wechat/fans/detail` | `{ accountId, openid }` | `{ fan, related: Array<{ accountName, openid, subscribedAt }> }` | 详情 + 跨账号关联；related 按 unionid 查，unionid 为空时返回空数组 |
| `wechat/fans/sync` | `{ accountId, taskId? }` | `{ taskId, status, fetched, total, ... }` | 触发/续跑同步；单次调用最多处理 N 页（建议 5 页）后返回，前端可继续 |
| `wechat/fans/sync/status` | `{ accountId, taskId? }` | 最近一次任务快照 | 页面进入时展示同步状态与时间戳 |
| `wechat/fans/tag/create` | `{ accountId, name }` | `{ tag: WechatFanTag }` | `tags/create` |
| `wechat/fans/tag/rename` | `{ accountId, id, name }` | `{ tag: WechatFanTag }` | `tags/update` |
| `wechat/fans/tag/remove` | `{ accountId, id }` | `{ removed: boolean }` | `tags/delete`；二次确认由前端负责 |
| `wechat/fans/tag/members` | `{ accountId, openids, tagId, action: 'add' \| 'remove' }` | `{ succeeded, failed }` | `tags/members/batchtagging` / `batchuntagging` |
| `wechat/fans/remark` | `{ accountId, openid, remark }` | `{ updated: boolean }` | `user/info/updateremark`；remark 长度 ≤ 30 字符 |
| `wechat/fans/blacklist` | `{ accountId, openids, action: 'block' \| 'unblock' }` | `{ succeeded, failed }` | `tags/members/batchblacklist` / `batchunblacklist` |

**分发与守卫**：全部在 `src/modules/wechat/wechatRoutes.ts` 增加 case；对应 `isWechatFan*Request` 守卫放 `src/shared/types/wechat.ts`，与现有守卫同一风格（`isWechatAccountId` + 逐字段形态判定）。`openids` 限制为字符串数组且长度 ≤ 100（平台批量上限），超限直接拒绝，不静默截断。

### 3.4 错误码归一

现有 `client.ts` 的 `ERROR_HINTS` 只覆盖鉴权场景，运营接口需补一张**独立**映射表（不污染鉴权文案）：

| 错误码 | 场景 | 提示 |
|--------|------|------|
| `40164` | 全部 | 复用现有 IP 白名单提示 |
| `45009` | 同步/写操作 | 接口额度已用完，同步已保留进度，请稍后续跑 |
| `48001` | 标签/黑名单 | 该账号未获得此接口权限，请确认主体与后台权限 |
| `45104` | 批量打标 | 标签数超出平台限制（单个粉丝最多 20 个标签） |
| `40003` | 打标/拉黑 | openid 无效，可能已取关或不属于该账号 |
| `45016` | 标签重命名 | 标签名不合法（1–30 字符） |
| `45017` | 标签创建 | 标签数量已达上限（100 个） |
| `45018` | 标签删除 | 平台内置标签不可删除 |
| 网络失败 | 全部 | 复用 `NETWORK_ERROR_CODE`，提示可重试且不改账号状态 |

未登记错误码走兜底中文提示，不透出英文 `errmsg`；错误文本不写入日志与诊断包。

## 4. 页面与技术实现路径

### 4.1 信息架构

沿用 `AppPage` 骨架，三段 `SegmentedRail`：

| 分段 | 内容 | 页头 | 页脚 |
|------|------|------|------|
| **用户** | 搜索框 + 标签/状态筛选 + 用户列表 | 账号名、平台总数、快照时间、筛选结果数 | 「同步用户」主按钮 |
| **标签** | 标签列表（名称、人数）+ 行内重命名/删除 + 底部新建 | 标签数 | 「新建标签」主按钮 |
| **同步** | 最近一次任务结果卡 + 进度条 + 错误说明 + 「继续同步」 | 同步时间 | 「立即同步」 |

用户详情用 `Dialog` 承载，不新开页面：顶部身份（昵称、关注状态，不展示头像）、资料网格、标签编辑区、备注输入、UnionID 关联区、拉黑/解除按钮。

### 4.2 交互流程

```text
进入 fans 分区（account.id 为 key，切账号重挂载）
   │
   ├─ 读 wechat/fans/sync/status → 有快照？
   │     ├─ 有：直接读 wechat/fans/search 渲染本地快照，页头标「快照时间」
   │     └─ 无：回落 wechat/fans/list（实时首屏 100 位），页头标「实时数据 · 未同步」
   │
   ├─ 用户段：输入关键词 / 选标签 / 选状态 → 重新 search（本地过滤，无网络）
   │     └─ 点某行 → wechat/fans/detail → 详情弹窗
   │           ├─ 改备注 → wechat/fans/remark → 成功更新本地字段
   │           ├─ 勾选/取消标签 → wechat/fans/tag/members → 成功后按平台回读刷新
   │           └─ 拉黑/解除 → AlertDialog 二次确认 → wechat/fans/blacklist
   │
   ├─ 标签段：新建/重命名/删除 → 成功后刷新标签列表与用户标签
   │
   └─ 同步段：点「立即同步」
         → wechat/fans/sync（一次最多 5 页）
         → 展示进度：已拉取 / 平台总数、新增、更新、取关、失败
         → 未完成则显示「继续同步」；遇到 45009 保留游标并提示续跑时间
         → 完成后回写快照时间，用户段自动切到快照数据
```

**交互细节**

- 写操作期间全页按钮进入 `isMutating` 禁用态，避免并发重复提交。
- 搜索输入 300ms 防抖，只过滤本地快照，不触发平台请求。
- 标签筛选走 `wechat/fans/search` 的 `tagId`；结果为 0 时给「该标签下暂无已同步用户」空态，而不是「没有粉丝」。
- 已取关用户默认隐藏，通过状态筛选「已取关」查看；详情页明确标注取关时间未知。
- 同步不阻塞浏览：同步在宿主侧分批执行，前端可继续查看旧快照；每批完成刷新一次进度。
- 复制 OpenID/UnionID 用宿主提供的剪贴板通道，不直接调 `navigator.clipboard`（Webview 权限受限）。

### 4.3 权限控制

| 层 | 措施 |
|----|------|
| 宿主协议 | 所有方法走 `wechatRoutes` 白名单 + 类型守卫；`accountId` 必须是本地存在的账号，且写操作只作用于该账号 |
| 账号作用域 | `useWechatAccountScope` 提供当前账号；未选账号/账号被删时显示引导空态，不发任何用户请求 |
| 主体分级 | `verified === false` 时禁用黑名单与数据统计类入口并给出原因；标签与备注一般主体可用，但以 M0 实测为准 |
| 破坏性操作 | 删除标签、拉黑、批量取消标签必须 `AlertDialog` 二次确认，文案写明影响范围（如「已打标的粉丝会同步取消」） |
| 输入约束 | OpenID 批量 ≤ 100、备注 ≤ 30 字符、标签名 1–30 字符、标签总数 ≤ 100；前端与宿主双重校验 |
| 敏感信息 | OpenID/UnionID 列表脱敏；完整值只在详情弹窗按需复制；日志与诊断包不记录 |
| 并发与幂等 | 同一账号同时只允许一个同步任务；写操作携带 `accountId + openids` 的幂等校验（重复提交直接忽略），不依赖平台幂等 |

> 本项目没有多用户角色体系，权限边界是「账号作用域 + 平台接口权限 + 破坏性操作确认」，不引入 RBAC。

### 4.4 异常与边界

| 场景 | 处理 |
|------|------|
| IP 白名单未配（40164） | 页头状态变红并展示现有可执行提示，列表回落空态，不整页崩 |
| 平台未认证（48001） | 对应写操作禁用并显示「该账号未获得此接口权限」，保留只读浏览 |
| 当日额度用尽（45009） | 同步任务置 `partial`，保存游标；提示「稍后续跑」而非「失败」 |
| 头像/昵称缺失 | 平台自 2021-12-27 起两者均返回空值；界面不展示头像，昵称优先回落为公众号后台备注，再回落 openid 前 8 位；不视为异常 |
| UnionID 为空 | 详情页显示绑定引导；跨账号关联区显示「暂无可关联记录」，不报错 |
| 已取关用户 | 平台资料接口可能缺字段；只保留 openid + 状态，界面标注「已取关」且不显示关注时间 |
| 平台 openid 与本地快照数量不一致 | 页头同时显示「平台总数 N / 已同步 M」，不虚构「全部加载」 |
| 标签数与平台 count 不一致 | 以 `tags/get` 的 count 显示人数，单用户标签以资料接口 `tagids` 为准 |
| 同步中途断网 | 任务置 `failed` 并保留 `cursor + fetched`；下次「继续同步」从游标恢复 |
| 账号切换/删除 | 页面按 `key={account.id}` 重挂载；删除账号时清理三张新表的该账号数据 |
| Webview 弹窗被关闭 | 写操作在宿主侧完成，前端状态用 `reload()` 重建，不假设请求一定完成 |

### 4.5 同类应用案例参考与取舍

| 案例 | 可借鉴点 | 本项目的取舍 |
|------|----------|--------------|
| 微信公众号后台「用户管理」 | 按标签筛选、备注、黑名单、关注时间排序 | 全盘沿用信息结构，但把宽表压成 `Item` 列表 |
| 壹伴 / 微伴助手 | 用户详情侧栏、批量打标、同步时间戳常驻、操作前明确影响范围 | 采用「详情弹窗 + 批量选择 + 页头同步时间」；不做画像与群发 |
| 企业微信客户联系 | 外部联系人标签、同步状态可见、失败可重试 | 借鉴同步任务状态机与断点续跑，不做客户联系专属字段 |
| 新榜 / 西瓜数据 | 粉丝增长与来源维度 | 归 `stats` 分区，不在用户管理页堆统计卡片 |

**实现取舍结论**：功能完备性优先于信息密度——宁可让用户在三段之间切换，也不在 300px 宽面板里塞多列数据网格。

## 6. 测试与验收标准

### 6.1 单测清单（Vitest，不触网不落库的部分）

| 用例 | 断言 |
|------|------|
| `isWechatFanSearchRequest` | 拒绝非法 status、超长关键词、非数字 tagId；接受全缺省 |
| `isWechatFanTagMembersRequest` | `openids` 非数组、>100、含非字符串均拒绝；action 只接受 add/remove |
| `isWechatFanRemarkRequest` | remark 非字符串、超 30 字符、空白串拒绝 |
| `isWechatFanBlacklistRequest` | 空 openids 拒绝；action 取值收窄 |
| `readWechatFanProfile` | unionid 缺失时字段为 undefined；subscribe_time=0 不产生订阅时间；昵称原样保留（回落逻辑在服务层） |
| `mergeFanProfiles` | 100 个 openid 分批后无遗漏；资料缺失的 openid 保留降级条目 |
| `nextSyncCursor` | 平台 next_openid 为空时标记末页；中断后返回上次游标 |
| `describeFanError` | 45009/48001/45104 命中专属文案；未知码走兜底；不含英文 errmsg |
| `maskWechatIdentifier` | openid/unionid 只露尾号 6 位；短串不崩 |
| `tagIdsJson` | 乱序重复输入归一为升序去重 |

### 6.2 人工验收（沿用上位文档 AC 编号，续编）

| 编号 | 场景 | 指标 |
|------|------|------|
| AC-28 | 列表与总数 | 平台 120 位、已同步 100 位时，页头显示「共 120 / 已同步 100」，不声称全部加载 |
| AC-29 | 快照回落 | 无快照时展示实时首屏 100 位并标注「实时数据」；同步后自动切到快照 |
| AC-30 | 检索筛选 | 关键词、标签、关注状态三者叠加命中正确；结果为 0 显示对应空态 |
| AC-31 | 详情字段 | 详情展示 openid 尾号、unionid 尾号、地区、语言、关注来源、标签与备注；可复制完整值 |
| AC-32 | UnionID 关联 | 两个绑定同一开放平台的账号下，同一用户详情页互见关联记录；未绑定账号显示引导且不报错 |
| AC-33 | 标签 CRUD | 新建/重命名/删除后 `tags/get` 回读一致；删除前确认文案含影响说明 |
| AC-34 | 打标与解绑 | 批量给 2 人打标后，平台回读 `tagids` 一致；取消后标签数同步减少 |
| AC-35 | 备注 | 修改备注后平台回读一致；超 30 字符被前端拦截 |
| AC-36 | 黑名单 | 拉黑二次确认生效；解除后用户重新出现在列表；未认证账号入口禁用并说明原因 |
| AC-37 | 同步完整性 | 平台 250 人时分 3 页拉取、每批 ≤100 个资料请求，最终快照 250 条，无漏人 |
| AC-38 | 同步续跑 | 第 2 页断网后任务 `failed` 且保留游标；恢复后继续同步不重复计入已完成页 |
| AC-39 | 额度边界 | 45009 时任务 `partial`，提示续跑而非失败，游标不丢 |
| AC-40 | 账号隔离 | 切换账号后列表、标签、同步任务均不串号；删除账号后新表对应行被清理 |
| AC-41 | 脱敏 | 列表与日志中无完整 openid/unionid；复制按钮由宿主通道完成 |
| AC-42 | 错误权限 | 40164/48001 展示中文可执行提示，不出现英文 errmsg，账号状态按既有规则更新 |

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 目标账号未绑定开放平台 | unionid 全为空，F3 关联区永远空 | M0 先确认；未绑定时把关联区降级为引导文案，不把它当功能缺陷 |
| 平台写接口权限与文档不符 | F4–F6 不可用 | M0 实测回填；不可用时保留只读 + 「到公众号后台操作」指引，不放无效按钮 |
| 昵称头像自 2021-12-27 起返回空值 | 列表可读性下降 | 界面不展示头像；昵称优先用公众号后台备注，再回落 openid 前缀；不把昵称当唯一标识 |
| 100 与 1 万上限错位导致漏人 | 同步结果不完整 | 严格按 100 分批补资料；`fetched` 与 `total` 并列展示，不隐含「全部」 |
| 同步撞当日额度 | 任务中断 | 游标持久化 + `partial` 状态 + 续跑；不做无脑重试 |
| 平台是唯一真相但本地有写操作 | 快照短暂不一致 | 写成功后立即按平台回读刷新该用户；失败保留旧值并提示 |
| 窄侧栏信息过载 | 用户找不到操作 | 三段分区 + 详情弹窗；写操作只放页脚与详情内固定位置 |
| 敏感标识泄露 | 合规风险 | 列表脱敏、日志不记录、复制走宿主通道；遵循最小必要 |
