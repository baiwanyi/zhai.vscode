> **文档版本**：v4.0（VSCode 插件形态）

## 1. 四期划分总览与依据

### 1.1 划分原则

| 原则 | 说明 |
|------|------|
| **优先级优先** | 用户指定 `ai-press-notes` 三类（Notes / AI-Chat / Press）最高优先，先于其余模块落地 |
| **依赖前置** | Common / Markdown-ONE / Knowledge-Base 为地基与 AI `@` 上下文检索弹药，必须先行 |
| **核心闭环先行** | 第一期打通「写笔记 → 检索 → AI 改稿/问答 → 知识库溯源」，一次交付即可日常写作 |
| **工作量均衡** | 每期 AI 辅助工时 18~52 人·天，避免单期过重 |
| **可验证里程碑** | 每期结束有明确交付标准与可部署增量版本 |

### 1.2 线路维度定义

本项目为 VSCode 插件，按职责划分为 4 条「线路」（对应 shop.dev 的后端/前台/小程序）：

| 线路 | 含义 | 典型任务 |
|------|------|----------|
| **EH**（扩展宿主） | VSCode 扩展 API：命令/菜单、`FileSystemWatcher`、`Webview` 注册、`SecretStorage`、剪贴板 | 命令注册、增量监听、密钥、图片粘贴 |
| **WV**（Webview 前端） | React 面板 UI 与交互：笔记树、AI 面板、Press 树、阅读器、Dashboard | 面板组件、虚拟滚动、diff 视图 |
| **DB**（索引数据层） | SQLite / better-sqlite3 / FTS5 / 索引流水线 | DDL、分块、BM25、增量、溯源 |
| **AI**（AI 服务层） | DeepSeek / SSE / diff / `@` 上下文 / 预算护栏 | 流式、续写、用量、护栏 |

### 1.3 四期总览

| 第一期（第 1~10 周） | 第二期（第 11~17 周） | 第三期（第 18~23 周） | 第四期（第 24~29 周） |
|:----------------------|:-----------------------|:-----------------------|:-----------------------|
| ★ Common 通用底座 | ★ Press 作品/卷-章树 | ★ Reader 书架/虚拟滚动 | ★ 微博浏览器（OAuth2/时间线/评论/发布） |
| ★ Markdown 管线 | ★ Press AI 续写/润色/对话 | ★ 全局搜索跨模块聚合 | ★ 公众号写作/发布/管理 |
| ★ Notes 笔记核心 | ★ Press 角色/设定/大纲/伏笔 | ★ 模块联动（图库-笔记-写作） | ★ Dashboard 首页 Webview |
| ★ Knowledge-Base | ★ Press 导入导出（EPUB/PDF） | ★ KB 混合检索增强 | ★ 浏览器扩展（截图OCR/选中/整页） |
| ★ AI-Chat（双模式/diff/@） | ★ Press 统计/番茄钟 | ★ Reader 书签/全文搜索 | ★ 打磨（性能/测试/文档） |
| **里程碑：★ 创作核心闭环可用** | **里程碑：★ 长篇创作全链路** | **里程碑：★ 阅读+搜索联动** | **里程碑：★ 正式发布** |

### 1.4 工期估算说明

- 估算基于 **1 人使用 AI 辅助全栈开发**；单位 **人·天** = 1 人有效工作约 5 小时（AI 压缩编码时间，但设计/调试/集成按完整工时计）。
- 每周按 4~5 个工作日计有效开发时间（含设计评审、调试、联调）。
- 各阶段「人·天」为该阶段开发总工时（含 EH + WV + DB + AI + 测试）。
- 全部状态符号：⬜ 计划（全新项目，无既有实现）。

## 3. 第二期：小说写作 Press
